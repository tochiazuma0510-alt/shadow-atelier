**(b) \(j\) の欠落。** §1 Lane P:

> `PENT_W([m, f̄]) ⟺ ρ⁴(f̄)ρ³(f̄)ρ²(f̄)ρ(f̄)f̄ = 1`

正本 **定義 HSP-T** は \(\bar\rho^4(\bar f)\cdots\bar f=1\) **in \(Q\)**、ただし \(\bar f:=j(f)W\in Q\)。すなわち ρ は \(Q\) 上の自己同型で、**f̄ は P の元ではない**。正本は同じ記号 f̄ を P 側と Q 側で使い回しており(正本側の記法の弱点)、本稿はそれを曖昧なまま転記した。cond2 cert は正しく規約を宣言している:

発注文のまま実装すると型不整合、または実装者が \(j\) の規約を独自に選ぶ。**(a) と (b) は連動している** — 正規形で受け取ると \(j\) を適用する対象が復元できない。

### R-12 突合工程が「手で比較」— 規模と規律の両方に反する

- §1 図「司令塔突合(3 cert を並べて**手で比較**)」・§5.2-1「**3 ファイルを並べて**候補ごとに 3 つ組を作る」。R-1 の規模(70 万対)では不可能。
- §5.2-4 は同じ工程を「**機械的に合成**」と書いており、**同一文書内で矛盾**。
- 記憶の規律(報告の値は機械生成のみ・手写し禁止)にも抵触。
- ⟹ 第四の主体の突合器は**スクリプト+ハッシュ**として成果物化すること。そのスクリプトは 3 レーンの driver とも別著者で書く必要があり、**その独立性条件も本稿に書かれていない**(第四の主体の import 禁止表が無い)。

### R-13 三値(UNKNOWN)の置き場が無い

- 各レーンの出力は PASS/FAIL の二値。**CV-9-3 は PASS/FAIL/UNKNOWN の三値**を要求し、工房規律は「UNKNOWN は一級の結果」。
- 時間切れ・pc 群での評価失敗・代表元の取り直しが必要な候補の行き先が cert 様式に無い ⟹ 実装者は「とりあえず FAIL」に倒すか黙って落とす。
- §5.2-5「ここで初めて cross-checked を名乗れる」も、**CV-9 が UNKNOWN を返した場合の分岐**を書いていない。

### R-14 計算量 cap と撤退条件がゼロ(罠 #12 の不履行)

正本 §5.3 は **罠 #12「計算量予測に |Q|・|[P,P]|・|𝒳_N| を記録」**を明示するが、本稿にはメモリ/時間/候補数の上限も、超過時の行き先も無い。効く数:

| 量 | 値 | 効く先 |
|---|---|---|
| \(|P|\) | 5,764,801 = 7⁸ | Lane S/V の pc 群 |
| \(|[P,P]|\times|\mathcal X_N|\) | 117,649 × 6 = **705,894** | Lane S の列挙規模 |
| \(|Q|\) | 7⁴⁰ ≈ 6.37×10³² | Lane P の pc 群 |
| Lane S 通過件数 | ★ **どの予言も述べていない** | Lane P のコストが**発注時点で未知** |

### R-15 付録 A の family サイズの理由づけが誤り(4 と 5 の取り違え)

> 「h₄ᵗ(t=0..4, **p=5 なので 𝒳_N の元は 4 個**)」

- dummy family は **m=0 固定**の族(§8.3.2)であり **𝒳_N は関与しない**。族の大きさは ord(h₄) = p = **5**(t=0..4)、|𝒳_N| = p−1 = **4**。
- 数(t=0..4 の 5 個)は結果的に正しいが、**理由が違う量を指している**。実装者が 4 元だけ走らせる誘因になる。NW-P7 の正本は「**5 元中 5 元**」。
- 対照: §4 の p=7 側は「t=0..6」= 7 元で、NW-P6「p=7 の dummy family **7 元**」と整合(= p 元)。規則は「族の大きさ = p」であって「= |𝒳_N|」ではない。

### ★ N-1【重大】較正スイート全体が語規約の反転に盲目(pin が開いた正本による)
