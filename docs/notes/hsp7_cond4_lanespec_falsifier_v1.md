**(b) \(j\) の欠落。** §1 Lane P:

> `PENT_W([m, f̄]) ⟺ ρ⁴(f̄)ρ³(f̄)ρ²(f̄)ρ(f̄)f̄ = 1`

正本 **定義 HSP-T** は \(\bar\rho^4(\bar f)\cdots\bar f=1\) **in \(Q\)**、ただし \(\bar f:=j(f)W\in Q\)。すなわち ρ は \(Q\) 上の自己同型で、**f̄ は P の元ではない**。正本は同じ記号 f̄ を P 側と Q 側で使い回しており(正本側の記法の弱点)、本稿はそれを曖昧なまま転記した。cond2 cert は正しく規約を宣言している:

発注文のまま実装すると型不整合、または実装者が \(j\) の規約を独自に選ぶ。**(a) と (b) は連動している** — 正規形で受け取ると \(j\) を適用する対象が復元できない。

- §3-5 / §7-2: 各レーンは走行前に cond2 cert の既知値(|P|=7⁸・LCS [2,1,2,3]・|[P,P]|=7⁶)を「突合欄限定」で参照してよい。
- 実装者は単一文脈のエージェントであり、7⁸ を読んだ後に「一致するまで構成を直す」ことを**構造的には防げない**。P101-1 (4)「期待値をコード生成に使わない」の実効性が**読み順**に依存する。
- 安価な修理: **二相化**。(相 1) 自分の測定値を出力し digest を cert に固定 → (相 2) **その後で**アンカー cert を開いて突合欄を埋める。cond2 自身が note で「予測はコード生成に一切使っていない」と宣言しているので、同じ規律を**順序として**明文化すればよい。

### R-12 突合工程が「手で比較」— 規模と規律の両方に反する

- §1 図「司令塔突合(3 cert を並べて**手で比較**)」・§5.2-1「**3 ファイルを並べて**候補ごとに 3 つ組を作る」。R-1 の規模(70 万対)では不可能。
- §5.2-4 は同じ工程を「**機械的に合成**」と書いており、**同一文書内で矛盾**。
- 記憶の規律(報告の値は機械生成のみ・手写し禁止)にも抵触。
- ⟹ 第四の主体の突合器は**スクリプト+ハッシュ**として成果物化すること。そのスクリプトは 3 レーンの driver とも別著者で書く必要があり、**その独立性条件も本稿に書かれていない**(第四の主体の import 禁止表が無い)。

### R-13 三値(UNKNOWN)の置き場が無い

- 各レーンの出力は PASS/FAIL の二値。**CV-9-3 は PASS/FAIL/UNKNOWN の三値**を要求し、工房規律は「UNKNOWN は一級の結果」。
- 時間切れ・pc 群での評価失敗・代表元の取り直しが必要な候補の行き先が cert 様式に無い ⟹ 実装者は「とりあえず FAIL」に倒すか黙って落とす。
- §5.2-5「ここで初めて cross-checked を名乗れる」も、**CV-9 が UNKNOWN を返した場合の分岐**を書いていない。

### R-14 計算量 cap と撤退条件がゼロ(罠 #12 の不履行)

正本 §5.3 は **罠 #12「計算量予測に |Q|・|[P,P]|・|𝒳_N| を記録」**を明示するが、本稿にはメモリ/時間/候補数の上限も、超過時の行き先も無い。効く数:

| 量 | 値 | 効く先 |
|---|---|---|
| \(|P|\) | 5,764,801 = 7⁸ | Lane S/V の pc 群 |
| \(|[P,P]|\times|\mathcal X_N|\) | 117,649 × 6 = **705,894** | Lane S の列挙規模 |
| \(|Q|\) | 7⁴⁰ ≈ 6.37×10³² | Lane P の pc 群 |
| Lane S 通過件数 | ★ **どの予言も述べていない** | Lane P のコストが**発注時点で未知** |

- 最後の行が要点: NW-P1〜P8 のどれも Lane S の件数を予言しない。**Lane P のコストは通過集合の大きさに比例するのに、その大きさは事前登録されていない。** RAM 8GB・GAP `-o 2g` の制約下で cap 無しの発注は危険。
- 併せて「Lane S の件数は**予言ではなく探索結果**である」ことを cert に明記すること(S-7′ の突合表に混ぜると、後から件数を予言だったことにできてしまう)。

### R-15 付録 A の family サイズの理由づけが誤り(4 と 5 の取り違え)

> 「h₄ᵗ(t=0..4, **p=5 なので 𝒳_N の元は 4 個**)」

- dummy family は **m=0 固定**の族(§8.3.2)であり **𝒳_N は関与しない**。族の大きさは ord(h₄) = p = **5**(t=0..4)、|𝒳_N| = p−1 = **4**。
- 数(t=0..4 の 5 個)は結果的に正しいが、**理由が違う量を指している**。実装者が 4 元だけ走らせる誘因になる。NW-P7 の正本は「**5 元中 5 元**」。
- 対照: §4 の p=7 側は「t=0..6」= 7 元で、NW-P6「p=7 の dummy family **7 元**」と整合(= p 元)。規則は「族の大きさ = p」であって「= |𝒳_N|」ではない。

## 3. 【軽微】

- **R-16 「P の二重実装」が買う独立性は小さい**(害はないが §3-2 の位置づけは過大)。F₂ は 2 生成自由群、class 4 / exponent 7 の p-quotient、しかも**両レーンとも同じ `pq.exe` を同じ ANUPQ 経路(付録 B)で叩く**。実質的な自由度は pcgs の並びだけで、そこは R-4 の交換形式問題の原因側。実の独立性は **hexagon 評価(簡約 (3.10)(3.11) vs full (3.3)(3.4))**にあり、CV-9 の主論拠はそちらに据えるほうが正確。
- **R-17 §6 の分離表の粒度が判読不能。** 「実装スタイルが意図的に異なっていることが**望ましい**」(§6-3)は判読者が判定できる述語ではない。**宣言可能な軸**(生成元記号と順序・交換子規約 `Comm(a,b)=a⁻¹b⁻¹ab` か否か・左正規化の向き・θ/τ/ρ の向き・j の像・serialization)を `conventions_used` の欄として列挙し、レーンごとに値を書かせる形に(cond2 cert が既にその一部を持っている)。
- **R-18 CV-13(向き自己検査)への言及なし。** CV-13 は新規 probe の**必須テンプレ**で、かつ射程限定として「生成器と受理器が同じ誤った向きを共有すれば**一様な鏡像は素通りする**」「⟹ **外部 anchor または独立 source-map route を必ず併置**」を課す。本稿は 3 レーンとも**同じ紙の定義**から向きを取る(§6 の出典行が明示)ので、**一様な鏡像誤りは 3 レーン一致を素通りする**。三レーン一致は CV-13 の言う外部 anchor ではない。
- **R-19 §6「数学的定義の出典」の Lane V 欄**が「定義ノート (3.3)(3.4)」とだけ書き、**ファイル名・§番号が特定されていない**(Lane S/P は §8.7 等で特定済)。判読者が突合できる粒度に。
- **R-20 `candidates_in` 自身の digest が無い。** §5.1 は `candidates_in_source_cert_sha256`(source cert 全体)しか持たない。**自分が実際に読み込んだ値の列の digest** が無いと、抽出時の取りこぼし・順序変更・部分読みを検出できない。
