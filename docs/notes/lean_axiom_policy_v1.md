# Lean 公理化方針 v1(研究者裁定 2026-08-01・裁定 332)

**原則**: Lean 化で Mathlib に無い定理は、通常の数学の公理に加えて **公理(axiom)としてブラックボックス化して追加**する。何を公理として追加したかは**明示**し、公理を使用する箇所には**必ずコメント**を入れる。(研究者原文の方針。)

## 実装規約(司令塔強化 4 点・研究者方針の施行細則)

1. **機械追跡が主・コメントは副**: 全公理は namespace `ShadowAxioms` 配下に宣言。主定理群には CI で `#print axioms` を走らせ、**出力 ⊆ 公理台帳(§manifest)を機械照合**(未申告公理・sorryAx の混入を fail-closed 検出)。コメント(出典・理由)は人間用 — ドリフトし得るため保証は カーネル側(CV-12 の精神)。
2. **言明監査**: 各公理の Lean 言明は (a) 原論文と逐語照合(Sol 監査対象・画像照合の流儀) (b) **sanity インスタンス**(公理の小さな帰結を既知値で独立検証・言明ミスの検出網) (c) **使用する最弱形で言明**(M2-DESC の「BCL 粗形のみ」の紙規律を移植)。
3. **階層(v1.1 訂正・研究者指摘 2026-08-01)**: 分類基準は「誰が書いたか」でなく**認識論的な格**。**T1 古典**(Belyi・Weil 降下等・出典明確)/ **T2 論文固有**(2405 Thm 5.3・2008 Cor 2.8 等 — 監査済みでも「人間の論文依存」と明示)/ **T2b 標準的・精密出典未特定**(TB1/TB3/TB4ᵘ/A3 — folklore 級・**自前再導出の紙が既にあるため、将来は Mathlib 待ちでなく再導出自体の形式化で公理を消せる**)/ **T3 真に未証明の仮説**(FAITH 等)— **T3 は原則 axiom にしない**: 定理の言明に明示仮定(`(h : _) → …`)として載せ、型に条件性を運ばせる。全域で要る場合のみ `assumption_` 接頭辞の最終手段。
5. **差し替え規約(研究者方針)**: 公理は Mathlib 到着待ちのプレースホルダ。台帳に **Mathlib 状況欄**(不在/PR/取込済)を持ち、到着時は公理宣言を Mathlib 参照へ置換 — CI の `#print axioms` 照合が「公理が減った」ことまで機械検証する。T2b は Mathlib を待たず自前再導出の形式化でも消せる。
4. **公理台帳(manifest)**: `lean/AXIOMS.md`(Lean 線始動時に新設)— 公理名・階層・原典(定理番号+照合記録の裁定番号)・Mathlib 不在の確認方法・使用箇所一覧。追加は司令塔裁定を経る(勝手な公理追加の禁止)。

## 既存方針との関係

- framework-assumptions-policy(2026-07-28「Lean 化せず Mathlib 待ち」)を**本方針が更新**: 待たずに T3 assumption として形式化に含める(格の明示つき)。
- 「verified」の語は従来どおり Lean 通過に予約 — ただし公理つき検証は **verified-modulo-axioms(公理台帳参照)** と表記し、無印 verified と区別する。

## v1.2 追補(研究者指摘 2026-08-01・裁定 334)

6. **終状態不変量**: 公理台帳の最終形は **T1/T2 のみ**。T2b は建設中の足場としてのみ許容 — 各 T2b 公理は自前再導出ノートへのリンクと形式化予定を必須とし、**CI が T2b 残数を警告**(単調減少の監視)。T3 は公理として**恒久禁止**(言明の明示仮定のみ)。根拠: T2b の再導出自体が T1/T2 級の事実だけから組めるはずなので、最終的に境界に残るのは T1/T2 のみ。
7. **宣言箇所 doc-comment(単一ソース)**: 全公理は宣言直上の `/-- … -/` に定型フィールド(内容の一行説明・原典+定理番号・階層・逐語照合の裁定番号・Mathlib 状況)を必須とし、**AXIOMS.md はこの doc-comment 群から機械生成**する(手書き台帳とのドリフト根絶・CV-12)。使用箇所コメント(v1 原則)と併用。

## v1.3 追補(研究者裁定 2026-08-01・裁定 335)— T2b 廃止・着工条件の新設

- **公理階層は T1/T2 の 2 つのみ**。T2b(足場公理)は**廃止** — 「T2b を入れなければならない段階なら、そもそも Lean 化しない」(研究者原文)。
- TB1/TB3/TB4ᵘ/A3 等の標準事実は公理候補でなく**形式化すべき補題**(自前再導出の紙から T1/T2 公理の上に証明する側)。
- **着工条件(entry criterion)**: 証明鎖の Lean 化は、全依存が ①形式化済み補題 ②T1/T2 公理化可能 ③言明の明示仮定、のいずれかに割り付くと確認できた鎖のみ着工。割り付かない依存が残る鎖は着工しない(先に再導出を形式化するか待つ)。
- v1.2 の「T2b 足場+CI 残数警告」は本追補で失効(台帳は最初から T1/T2 のみ・不変量でなく前提条件になった)。

## v1.4 追補(研究者裁定 2026-08-01・裁定 336)— T3 も廃止・最終形

- **T3(明示仮定としての未証明仮説)も方針から廃止**: 未証明の仮説が言明に残る鎖は数学として未完成であり、**着工しない**(条件つき定理の形式化という中間形も採らない)。
- **最終形**: Lean 化するのは **T1/T2 公理+形式化済み補題だけで完結する鎖のみ**。公理階層は T1/T2 の 2 つ。着工条件 = 全依存が {形式化済み補題, T1/T2 公理化可能} に割り付くこと。
- 位置づけ: Lean は完成した数学の**封印**であって探索の道具ではない(発表保留・理解所有の方針と同一線上)。v1.2 §6・v1.3 の T3 関連記述は本追補で失効。

## v1.5 追補(研究者裁定 2026-08-01・裁定 338)— 構造化規約(切り出し義務)

- **切り出し義務**: 紙の証明が「標準理論により」「TB1 により」等で暗黙に使っている事実は、Lean 化時に**すべて名前つき補題・定理として切り出し、T1/T2 公理から証明する**。無名のインライン步として仮定を残さない — 仮定に見えていたものは Lean では証明義務になる。
- **1:1 対応の双方向維持**: 紙の補題 ⟷ Lean の補題は 1 対 1(paper-style-lean 既定)。Lean 側で新たな切り出しが必要になったら**紙側にも同じ補題を追記**して対応を保つ(Lean が紙の暗黙を暴いたら紙を直す)。
- **着工判定との一体化**: 着工条件(v1.3)の「依存の割り付け表」= **補題分解計画**を兼ねる — 各依存に対し {名前・言明・出所(T1/T2 公理 or 切り出し補題)・証明の状態} を列挙してから着工。

## v1.6 追補(Sol 便 95 検収・裁定 345)— 施行ゲート 6 点(P95-4.1)

Sol 判定: v1.4 は施行条件つき PASS(F95-4.3)。「kernel が確認するのは公理から結論が導かれたことであって公理の真偽ではない — T1/T2 の格は provenance 層」。着工時の必須ゲート:

1. **公理ごとの束縛**: 原典の exact theorem/頁・PDF 画像照合の裁定番号・使用する最弱形・sanity instance を束縛。
2. **Mathlib 不在主張の相対化**: Mathlib commit/toolchain を pin し、その版に相対化して主張(「不在」は版つき事実)。
3. **`#print axioms` の全量照合**: `ShadowAxioms` 名前空間だけでなく**出力の全 axiom** を取得し、許可済み Lean baseline+生成 manifest の和以外を拒否。`sorryAx` は常に FAIL。
4. **receipt への exact axiom set 束縛**: project manifest は superset 可だが、各主定理 receipt には実際に出た **exact sorted axiom set** を束縛。
5. **doc-comment 台帳の drift 防止**: 生成台帳には説明文だけでなく **axiom declaration の正規化した型またはその digest** も入れる(説明と Lean proposition の乖離検出)。
6. **M2-DESC の形式化方針**: 広い BCL を axiom 化するより **F95-1.4 の二次拡大直接降下(明示同型+有限降下)を形式化**する方が axiom boundary が小さい — 着工時はこちらを既定とする。

注(W95-4.2): Sol の正式判定対象は v1.4 exact blob まで。v1.5(切り出し義務)は否定されていないが本便の digest には遡及混入させない — v1.5 以降は次便の監査対象。
