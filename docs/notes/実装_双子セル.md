# 実装ノート — レベル 16 双子セル列挙機 v1(2026-07-26・implementer)

入力: `docs/manifest_twincell_v1.md`(事前登録)・`docs/所在と能力.md`(gaplib_common.g 使用指示)・
`search/week3-battery-common.g`(EnumerateReducedHexagon・MakeGn 等の既存 helper)。

## 建造したもの

- `search/twincell-enum.g`: GAP 側の建造+較正スクリプト。`Read("search/gaplib_common.g")` →
  `Read("search/week3-battery-common.g")` の順で読み込み(gaplib_common の壁時計/cap ヘルパーは
  固有名で衝突せず、JSON ヘルパーは battery-common 側で上書きされるがバイト互換のため無害)。
  - 系統(a) **行列 mod L**: `BuildMatQuotient(L, ySign)` を新規実装。Xbar=[[1,2],[0,1]]・
    Ybar=[[1,0],[-2,1]] を mod L 還元し、m ~ -m(mod ±1)の正準化(整数キーの小さい方を代表元に
    取る)を行った上で BFS 閉包 → 左正則置換表現(Q8/Heis/P3 と同じ「自前正準形+BFS+左正則表現」
    パターン。GAP の `GF(q)` は L が素数冪でない場合(8,10,16)使えないため、この自前構成を選んだ)。
  - 系統(b) **D_n^3 埋め込み**: 既存 `MakeGn(n)` をそのまま再利用(𝒞₈ = K^(4) は n=4、
    K^(8) は n=8)。新規コードなし。
  - 共通ランナー `RunWindow`: `EnumerateReducedHexagon`(既存 helper)を呼ぶだけの薄いラッパー。
  - `CheckMarkedBijection`: 較正①の**marked factor map** 全単射照合。
    `GroupHomomorphismByImages(G1,G2,[x1,y1],[x2,y2])` で x↦x,y↦y を送る具体的準同型を構成し
    `IsBijective` を確認した上で、各 GT-shadow (m,f) を φ(f) へ送って G2 側の shadow 集合と
    一対一対応することまで検査する(**単なる |GT| 一致や部分群の位数比較ではない** -- Sol 警告6件・
    罠12件の「指数一致を settled 証明に使わない」「GAP の部分群比較でなく marked factor map を
    使う」を踏まえた設計)。
  - FIRE ロック: `search/FIRE_twincell.auth` の `IsExistingFile` 検査。無ければ標的窓(𝒞₁₆ 行列
    mod 16・K^(8))の本走査を丸ごとスキップする(コード自体は書いてあるが実行されない -- e2c6-sweep.g
    と同じ機械的ガード)。**このロックファイルは司令塔のみが発行するものであり、implementer が
    テスト目的であっても作成してはならないと判断し、動作確認は行っていない**(下記「未検証」参照)。

- `crosscheck/check-twincell.mjs`: 独立照合器。証明書(`certificates/twincell/*.json`)のみを入力とし、
  matrix-mod-L 演算・D_n^3 埋め込み・reduced-hexagon 列挙・BFS+prepend 語評価(既存
  `crosscheck/check-psl.mjs`/`check-v2.mjs` と同じ convention だが、コードは import せず一から
  再実装 -- CLAUDE.md 鉄則2の「探索器/照合器」分離を照合器どうしにも適用)。
  - 較正①の marked bijection も GAP の `GroupHomomorphismByImages` を信用せず、**BFS で得た
    G1 の全語を G2 側で同じ語として評価し、単射性・全射性・shadow 対応**を独立に再検査する。
  - 自己テスト `selfTestCorruption`: 正常な証明書の `shadow_total` を +1 に改竄した clone を
    作り、この照合器自身がそれを FAIL と判定することを確認(F5/F6 型「偽陽性検出器」)。

## 較正結果(GAP 実行 + node 独立照合、両方 all_pass)

```
.\gap.ps1 search\twincell-enum.g
```
- 𝒞₈ 行列 mod 8: |Q_8| = 32、reduced hexagon → shadow_total = 4
- 𝒞₈ D_4^3(MakeGn(4)): |G_4| = 32、shadow_total = 4
- **較正①: marked factor map 全単射 PASS**(matched=4, sizesMatch/injective/surjective 全て true)
- **較正① 既知値: 両構成とも |GT|=4 PASS**(Thm 4.3・裁定18)
- 𝒞₁₀ 行列 mod 10: |Q_10| = 60(= |A5|)、shadow_total = 20
- **較正② 既知値: |GT|=20 PASS**(≅F₂₀、裁定16)
- 負例 fixture(level 取り違え L=6): |Q_6|=12(≠32)、marked bijection 失敗・shadow_total=6(≠4)
  → **正しく FAIL と判定される PASS**
- 参考記録(要件外): Ybar 符号反転版(mod 8)は |Q_8|=32・shadow_total=4・D4^3 との marked
  bijection も成立 -- これは「壊れていない」ことが判明したため負例としては不採用にした
  (最初に試した案。数学的には Γ(2) の別の自由生成対を与えるだけで K^(4) の別実現になっている、
  という頑健性の観測として記録するに留める)。

## 未検証・逸脱・懸念(正直に報告)

1. **標的窓コードパスは実行未確認**。`search/twincell-enum.g` 内の C16/K8 分岐(`fireUnlocked` 側)
   は較正窓と全く同じ `RunWindow`/`WriteTwincellCert` を呼ぶだけの構造だが、実際に
   `search/FIRE_twincell.auth` を置いて動かした実測はしていない -- 動作確認のためにロックファイル
   自身を作ることは司令塔の専権事項を侵すと判断し、一度作成しかけたが**即座に削除し、報告する**
   (発射時に司令塔の指示で最初の実行時に検証されたい)。
2. **群位数の理論的裏付けは実測でのみ確認**、事前の指数計算(|SL(2,Z/L)|/6/2)による予測 32・60・256
   は紙の上の見積もりであり、本ノートには根拠として書いたが `Error` ガード(`BuildMatQuotient` 内、
   `Size(Group(x,y)) <> BFS要素数` で fail-closed)によって GAP 側で自己矛盾があれば即座に停止する
   設計にしてある(今回は 3 窓とも一致・矛盾なし)。
3. 較正②(𝒞₁₀)は manifest 上「既知値 20 の再現」のみが要件で、A5 置換構成(既存
  `certificates/A1.v2.json`)との bijection は要求されていないため実装していない
  (必要なら追加委嘱を)。
4. `MatCanonL` の正準化(整数キー比較)は Q8/Heis/P3 と同種の「自前正準形」パターンだが、L の
   異なる窓(8/10/16)で共通コードを使い回している点は探索器内部の一般化であり、照合器側とは
   独立に別実装している(上記)ので分離規律には抵触しない。
