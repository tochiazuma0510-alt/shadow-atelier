### 項目 5 の詳細(不一致の中身を隠さず記載)

発注文の写像 (g0,g1) ↦ Fix(g1) を字義どおり実装した: g1 は (5,5,5) 三つ組の第二成分であり、**位数 5**(5-サイクル)である。S₅ の自然な作用({1,…,5} 上)において、位数 5 の元(5-サイクル)は**不動点を一つも持たない**(5 点すべてを動かす)。

実際に GAP で計算した結果、𝒟(v) の 5 個の対すべてで **Fix(g1) = ∅**(空集合)だった:

```
Fix(g1) for each g1 in D(v): [ [  ], [  ], [  ], [  ], [  ] ]
```

したがって:
- 写像は {1,…,5} への写像として**そもそも well-defined でない**(各 Fix(g1) が単集合でなく空集合)。ゆえに「全単射」の判定は **FAIL**(発注文の期待値 true と不一致)。
- 「⟨v⟩-同変性」は両辺が恒常的に空集合どうしの比較になるため機械的には PASS するが、**これは空虚な成立(vacuous truth)であり、写像が機能していることの証拠にはならない**。

**所見(判断はせず事実のみ)**: `docs/week4-A5算術飽和_v2.md` §3.6 の補題 FC-6 は (q,r) ↦ Fix(q) という**別の写像**を扱っており、そこでは q は **位数 2**(2A 型、A₅ の自然な 5 点作用でちょうど 1 個の不動点を持つ二重互換)である。今回の発注文 (a).5 は g0,g1 ともに**位数 5**の (5,5,5) 三つ組の文脈で同型の記法(𝒟(v)・Fix)を再利用しているが、g1 も位数 5 である以上、文字どおりの Fix(g1) は恒常的に空である。node 側がどのような写像を実際に計算して true を得たのか(あるいは発注文の記述が FC-6 の (2,3,5) 文脈の期待値を誤って本設問に転記したのか)は本実装からは判定できない — **司令塔への差し戻し事項**として報告する(黙って再解釈して「合わせ」に行っていない)。

### 訂正(2026-07-26・司令塔裁定): (a).5 は発注ミス — 正しい v2 §3.6 FC-6 仕様で再実行

司令塔が上記の FAIL 報告を受けて診断: **(a).5 は司令塔の発注文の転記ミス**であり、v2 §3.6 の補題 FC-6 は (5,5,5) 三つ組ではなく **(2,3,5) 対**の写像だった。正しい仕様で `search/a5-dessin-crosscheck.g` に追補・再実行(旧 (a).5 のコードはブロックとして無変更のまま監査痕跡として残置)。

**訂正仕様**: v=(1,2,3,4,5) を固定。𝒟(v) := {(q,r) : q ∈ 2A(二重互換・cycle type (2,2,1)、ちょうど1個の不動点), r ∈ 3A(3-サイクル), qrv=1}。「qrv=1」の語規約(紙の語順 vs GAP 積の語順)は両読みを並記:

| 規約 | 式(GAP) | \|𝒟(v)\| | Fix(q) 各要素が単集合(well-defined) | (q,r)↦Fix(q) 全単射 | ⟨v⟩ 共役で 𝒟(v) に閉じる | ⟨v⟩-同変性 Fix(vqv⁻¹)=v(Fix(q)) |
|---|---|---|---|---|---|---|
| **MAIN**(主・「全逆順」) | v*r*q = One(G) | **5** | PASS | **PASS** | PASS | **PASS** |
| NAIVE(素朴・語順どおり) | q*r*v = One(G) | **5** | PASS | **PASS** | PASS | **PASS** |

両規約で数値・判定が完全一致(5・PASS・PASS・PASS・PASS)。node 側期待値(𝒟(v)=5・全単射/同変=true)と**全一致**。

**実装上の注意点(見つけて修正したバグ)**: ⟨v⟩-同変性の検査で「q を v で共役する」操作を GAP で書く際、素朴に `q^(v^(-1))`(標準的な公式 x^a = a⁻¹xa に a=v⁻¹ を代入した形)を書くと **誤った答えを出す**ことを実測で確認した。GAP の `^` は `i^(g*h) = (i^g)^h`(右作用)という、標準的な関数合成と逆順の規約で自己完結しているため、「標準数学の意味での v q v⁻¹ かつ v(i) = i^v」という組み合わせを再現する GAP 式は `q^v` であって `q^(v^(-1))` ではない(`search/debug-equiv-test.g` で q=(1,2)(3,4), v=(1,2,3,4,5) の具体例で検証: q^v = (2,3)(4,5) の不動点 {1} = v(5) = v(Fix(q)) と一致するが、q^(v^-1) = (1,5)(2,3) の不動点 {4} は一致しない)。本プロジェクトの「paper 語 "AB" ↔ GAP 乗算 "B*A" の反転」(2026-07-26 WO2 A2 の教訓)と同種の罠。旧 (a).5 の同変性検査コードは(両辺が恒常的に空集合だったため)このバグの影響を受けずに PASS していたが、訂正仕様のコードでは修正後に正しく PASS した(修正前は両規約とも FAIL だった)。
