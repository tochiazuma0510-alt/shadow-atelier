## (b) 実測で確定した合成規約辞書(今後の GAP⇔python 突合で再利用する資産)

**検証方法**: 既存の A5窓(`search/probe/wac_v1/pent_t2t3_v3_20260731.g` の window 構築、S1/S2/S3 = `pent_pi_a5_export_sigmas.g` の輸出値)について、GAP 側で計算した `xb,yb,X13v,X34v,X24v,X14v,cof[1..5],cofc[1..5]` の **具体的な置換像リスト(domain [1..8])** を印字し、同じ S1/S2/S3 を python 側 `PaB.restr_PB4((S1,S2,S3))` に通して得た `t=(x12,x23,x13,x14,x24,x34)` の像リストと **数値として直接突合**した(定式の目視照合ではなく、実際の置換の出力一致による実測)。

確定した事実:

1. **`PaB.restr_PB4` の出力は GAP と同一の domain [1..8] 上で、変換なしに直接比較可能**(座標のシフトやドメイン再ラベリングは不要)。
2. **合成規約の対応**: PaB の `comp(s,t) := t*s`(sympy 積、doc 上「natural order = s を先に適用してから t」)は、**GAP の `S*T`(GAP標準: `i^(S*T)=(i^S)^T`、S を先に適用してから T)と直接対応する**(操作の引数順を入れ替えずにそのまま "GAP `S*T`" ↔ "PaB `comp(S,T)`" と読み替えてよい)。
   - 検証: `cof[3][1] = X23v*X13v`(GAP)の実像 `[2,3,5,1,4,6,7,8]` を、python 側で「x23 を先に適用しその後 x12 を適用」する素朴な点ごと合成 `i -> x12(x23(i))` で手計算したところ、完全一致した(`i=1..5`: `2,3,5,1,4`)。
3. **A5窓の6生成元とPaBの6生成元タプルの対応**(名前は対応しない・役割の相互対応のみ判明):
   - GAP `xb`(=X12v)= GAP `X34v` ⇔ PaB `x24`(像 `[4,1,2,5,3,...]` で完全一致)
   - GAP `yb`(=X23v)= GAP `X14v` ⇔ PaB `x23`(= PaB内部でも `x14` と一致、像 `[3,1,4,5,2,...]`)
   - GAP `X13v` ⇔ PaB `x12`(= PaB内部でも `x34` と一致、像 `[3,4,2,5,1,...]`)
   - GAP `X24v`(像 `[5,1,4,2,3,...]`)は PaB の6生成元のどれとも一致しなかった(単独の生成元としては対応先未確認 — 下記(c)の縮退が原因で positional な対応が付けられない)。

この辞書は「GAP の乗算順序 = PaB の comp() 引数順序」という一点さえ押さえれば、**以後どの窓についても座標変換の当て推量なしに GAP⇔python の置換を直接比較できる**という意味で、今後の全ての third-party 突合作業に再利用可能な資産である。

## (c) A5窓の π-lift 縮退の記録

A5窓(`pent_t2t3_v3_20260731.g` の window)は `σ3 ↦ σ1` という pi-lift 構成(`S3 := W.s1`、すなわち `sigma3` の像を `sigma1` の像に強制的に一致させる構成)を採用しているため、そこから導かれる PB₄ の6"生成元"のうち

- `X34v = X12v`(= `xb`)
- `X14v = X23v`(= `yb`)

の2組の**縮退(coincidence)**が生じており、実質的に **独立な生成元は4つ(xb, yb, X13v, X24v)** しかない。これは一般の PB₄ タプル(N19 の `t19` のように B₄ からの制限を経ない、あるいは pi-lift を課さない場合)には存在しない特殊性であり、(b)の対応表で `X24v` が PaB の生の6生成元のどれとも一致しなかったことの一因と考えられる(縮退により、A5窓の cof/cofc 構成は「一般の PB₄ 6タプルに対する PaB の fi123/fi234/fi12_3_4/fi1_23_4/fi1_2_34/cenPB3 公式をそのまま適用したもの」とは素朴には同一視できない — 前回セッションでの停止判断の技術的根拠)。
