# R0v2 第二系統検証 — 報告

## 方法(GAP 依存の切り離し)

GAP 起動は**生 Cayley 表の export のみ**(判定ロジックはゼロ行)。表・元の位数・単位元の添字だけを JSON で出し、以後は python で全て自前:群公理検査・部分群生成・braid 三つ組全探索・ψ(PB₄)・Δ₄²・**Aut(G) の自前構成**。GQuotients・IdGroup・IsAbelian・Order いずれの GAP 判定にも依存していない。

> 追加開示: 識別力対照(下記)のため raw export を**もう一度**呼んだ(対象群を増やしただけ・GAP 側ロジックは同じくゼロ)。

表の健全性: 単位元・**全行/全列が置換(ラテン方陣)**・結合律 400,000 サンプル・192 元の位数を表から再導出して export と一致 — 2 群とも OK。

## 発見した cert の欠陥 2 件(いずれも発見そのものは無傷)

**【重大 A】cert 内部矛盾 — p2 と p3 が 1492/1494 で食い違う。**
`p2_passed` は 1492・1494 に `N_idgroup: [[8,4]]`(= Q₈)を記録するが、同じ cert の `p3` は同じ群に `Q_idgroup: [8,5]`・`Q_is_abelian: true` を記録する。**私の独立計算は ψ(PB₄) ≅ C₂³ = [8,5](位数分布 (1,2,2,2,2,2,2,2)・可換)で p3 side に立つ。⟹ p2 の [8,4] は誤り**(1489/1490 の値の持ち回りに見える)。1489/1490 では p2・p3・私の三者が一致するので**主発見には影響しないが、P2 は「どの群を P3 に通すか」を決める段であり、その出力が信用できない。**

**【重大 B】取りこぼし — SmallGroup(192,1495) が消えている。**
1495 は B₄ の全射を **1152 本**持ち、ψ(PB₄) の位数は 8(C₂³・δ₂=1)、Aut 会計では **1 epi 類**。P1 は通過している(`Gab_size: 4` で記載)のに **p2_passed にも p3 にも現れない**。同じ核型 [8,5] の 1492/1494 は P2 を通っているので、**P2 の filter は文書化された基準と一致していない**(silent drop か未文書の絞り)。**窓ではない**(核可換・σ 位数 (4,4,4) = cert 自身が `is_window: false` とする型)ので **4 窓の主張は無傷**だが、sweep の網羅性主張は傷む。

**【要修正 C】記号 N の二義使用。** 同一 cert 内で `N_idgroup`(p2)は ψ(PB₄) を指し、`delta2_in_N` の N は **ker ψ** を指す。しかも **B₄ ↠ G の核は無限群**であり、Q₈ は**核ではなく ψ(PB₄)**(= PB₄ の像)である。司令塔メッセージの「核 Q₈」も同じ取り違えを引きずっている。欠陥 A の発生源もここである可能性が高い。**`psi_PB4_idgroup` と `delta2_in_ker` に改名すべき。**

## 結論

**[192,1489] と [192,1490] の 4 窓(各 2 epi・ψ(PB₄) ≅ Q₈・非可換・σ 位数 (8,8,8)・G/ψ(PB₄) ≅ S₄・δ₂ が二類を分離)は、GAP の判定機構に一切依存しない独立計算で完全に再現された。** 全滅方向のズレも過剰方向のズレも無い。Aut 軌道会計も epi 数 2 と厳密に整合。

**支持する**: 4 窓の存在と、その 6 つの測定値すべて。
**支持しない**: `p2_passed` の内容(1492/1494 の核型が誤り・1495 が欠落)。P2 段は再実行して cert を訂正すべき。sweep の「網羅した」型の主張は、P2 の filter が実際に何を落としているかを確定するまで保留を推奨。
