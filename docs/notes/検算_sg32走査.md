# 検算: 位数 32 全 51 群の (4,4,4)-marked F₂-商 悉皆走査

**発注**: 裁定_19_geography_v3.md §4「384/384 の昇格経路」— SmallGroup(32) 全 51 群に対する (4,4,4)-marked F₂-商の全走査で「位数 32 の (4,4,4)-marked 商は G₄ ただ一つ」を示す(marked bridge を presentation 経路と独立に閉じる「第二証明」)。

**スクリプト**: `search/smallgroup32-scan.g`(実行: `.\gap.ps1 search\smallgroup32-scan.g`、elapsed 1500ms)
**証明書**: `certificates/a5/smallgroup32_scan.json`

## 判定基準

各 SmallGroup(32,i) (i=1..51) について、G² 上の全 1024 対 (a,b) を総当たりし
`⟨a,b⟩ = G ∧ ord(a) = ord(b) = ord((ab)⁻¹) = 4` を満たす対の個数 N_i を数えた
(ord((ab)⁻¹) = ord(ab) なので実質 ord(a)=ord(b)=ord(ab)=4 の判定)。

## G₄ の同定

G₄ = ⟨(r,s,s),(rs,r,rs)⟩ ≤ D₄³(裁定_18_kcong.md の Gₙ ≤ Dₙ³ 構成の n=4 例)は
`search/week3-M5-explorer.g` の `MakeGn(n)`(n=3 で G3 として既に使用中)の n=4 版そのもの
(抽象規約 r^a s^e = GAP 表記 s*r^a、既存コードを転用・再導出せず)。

- |G4| = 32
- **IdSmallGroup(G4) = [32, 2]**
- G4 の定義対 (x,y) 自身: ord(x)=4, ord(y)=4, ord(xy)=4 — (4,4,4)-marked 条件を満たすことを確認(PASS)。

## 走査結果(全 51 群中、N_i > 0 の群)

| SmallGroup(32,i) | StructureDescription | N_i | \|Aut(G)\| | N_i/\|Aut\|(核の個数) |
|---|---|---|---|---|
| 32,2 (= IdSmallGroup(G4)) | (C4 x C2) : C4 | 384 | 384 | 1 |
| 32,6 | (C2 x C2 x C2) : C4 | 192 | 64 | 3 |

他 49 群はすべて N_i = 0(非(4,4,4)-marked-商群)。

補足数値(独立クロスチェックで一致確認済み):
- G2: 位数4の元 24 個・位数スペクトル [1×1, 2×7, 4×24]
- G6: 位数4の元 20 個・位数スペクトル [1×1, 2×11, 4×20]

## 判定文(機械事実のみ)

**反例あり**: 位数 32 で (4,4,4)-marked F₂-商になれる群は **SmallGroup(32,2) = IdSmallGroup(G4) だけではない**。
**SmallGroup(32,6)(= (C2×C2×C2):C4)も N_6 = 192 > 0 で非零**であり、核の個数は N_6/|Aut(G6)| = 3。

したがって発注文で仮定されていた「位数 32 の (4,4,4)-marked 商は G₄ ただ一つ」という予測は
**この全数走査によって不成立と判明した**(384/384 の昇格経路は閉じない・marked bridge の
「第二証明」はこの形では成立しない)。G4 (SmallGroup(32,2)) 自身の N_2=384, kernels=1 は
確認どおり(裁定_18 の「384/384」という数値と整合)。

Sol 警告との関連(注意点として記録・断定はしない): 本走査は GAP の部分群比較でなく
`Size(Subgroup(G,[a,b])) = 32` による生成判定(marked pair 判定そのもの)であり、罠「GAP の
部分群比較でなく marked factor map を使う」は N_i の数え方自体には抵触しない設計のはず。
ただし SmallGroup(32,6) が非零になった事実は、司令塔・数学者による追加解釈(G4 と G6 の
marking の違い・F2 の別々の生成写像として区別すべきか等)を要する — この報告は判定文の
数値確定までであり、解釈判断はしていない。
