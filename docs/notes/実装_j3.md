## 実装済み項目(列挙形)

### GAP側(`search/e2c6j3-sweep.g`)

- 線型段(2 ブロック・30×15)を `BuildSnfData`/`TestAtJ`(`search/e2c6-common-data.g`、j 一般)
  で j=3(mod 8)に適用。
- `WMfun(m) = C(m+1,2) mod 2`、`LambdaOfK(k,m) = (k_p, k_s3+W(m)k_r2) mod 2`(便24 eq 8.3)。
- `QFirstCond(f) = (f_p, f_s3+f_w*f_r2) mod 2`(便24 eq 8.1 の実値、非線型のまま厳密評価)。
- `k_w ≡ 0 (mod 8)` 前提(便24 eq 8.2)の**検証**: safe な合成系(rhs=0、m=0,1,2,3,5,7,11)
  26 生成元で実測 PASS。
- **`CheckPremiseKw` ガード関数**: 生成元列を受け取り k_w≡0(mod8)を再検証、破れれば
  違反生成元を返す。**`RunRealSweepC6J3` は各 m でこれを呼び、違反時は
  `"claim":"precondition_violated_c6j3"` 証明書(`ob_mode:null`)を書いて当該 m の
  λ 適用を ABORT する**(黙って進まない)。この ABORT パス自体は、意図的に破った偽の
  生成元(k_w=1 を注入)を用いた GUARD fixture で検出動作を確認済み(実 64 系走査は
  fire lock により未実行のため、ガードの「本番での発火」自体は今回も未確認 — 検出ロジックの
  単体動作確認に留まる、と正直に記録する)。
- **重複度表の二系統**(λ-shortcut と brute-force)を全 fixture 系統で構築・完全一致を確認。
  λ-shortcut の出力には **2×d bit matrix(`lambda_bit_matrix`)と GF(2) rank
  (`lambda_rank`)を証明書に格納**(便24 F8 item 2)。
- **不可解系の dual witness**(便24 F8 item 1): `RunRealSweepC6J3` の不可解分岐で
  `y := U[failRow]; yM := y*rows; yb := y*rhs` を計算し証明書に格納(j=2 の
  `WriteUnsolvableCertC6` と同型)。この経路は、意図的に不可解な safe 合成系
  (`BuildLinearSystemC6AdversarialUnsolvableJ3` — 疑似乱数 rhs、実 Ē_m 不使用)で
  実際に発火させ、`yM≡0`・`yb≢0` (mod 8) を確認(fixture G1b)。
- **`ObFromQPair` の R=4 実演習**(司令塔発注 item3、便24 F8 とは別件): nonzero q_N の
  3 恒久ケース(F6 相当)を R=4 で実行(fixture G7)。結果: **ob mod 2 は q_N に依らず一定**
  (3 ケースとも確認)。**raw な R=4 座標(mod 2 を超えた a の意味論)は未解決のまま**
  (e2c6-sweep.g 自身の GAP-OB1 注記を踏襲 — 独自の公式は発明していない)。
- **周期性 fixture**(便24 F8 item 6、m/m+32、(3,35)(5,37)(21,53)(27,59)): `EmBar15 mod8`・
  `EmC6 mod4`・`W(m)` という**公開の Ē_m 公式データのみ**を両側で計算し証明書化。
  **一致・不一致そのものは pass/fail 判定に使わず「observed_equal」として記録のみ**
  (司令塔指示通り)。実測ではこの 4 組すべてで一致が観測されたが、これは fixture の
  合否条件ではない(観測事項として記帳)。
- **項目5(中心補正×8・直接群積 M8 との mass 照合)は未実装**。理由: 委嘱16 の語彙で
  「M8」は「群の積から θ(f)f と E_m N(f) を再計算して直接 =1 を確認する」検査を指し、
  これは fixture G3(route-G)がすでに closed-form との mod4 一致という形で部分的に
  カバーしているが、「中心補正 |kerΛ|=2^{e+1}=8 を掛けた full mass」という central
  extension の具体的な構成(kerΛ のリフト・8 個のファイバー元の直接列挙)は本パスでは
  設計されていない。**これは implementer の判断で自由に設計してよい範囲を超える
  (数学的構成の選択)と判断し、実装せずここに保留として明記する**。次便で司令塔/数学者に
  具体的な構成(central extension の生成元・関係式)の指定を仰ぎたい。

### 発射錠・ドリフト検査

- **発射錠の誤ハッシュ試験**: 誤ハッシュを書いた `search/FIRE_e2c6j3.auth` を実際に置いて
  `.\gap.ps1 search\e2c6j3-sweep.g` を実行 → `FIRE_e2c6j3.auth present but hash MISMATCH`
  → `[LOCKED]` を確認(壁時計 1 分以内、前回監査のタイムアウトは再現せず・原因は
  環境要因と推定、コード側の問題ではないと判断)。試験用ファイルは削除・現在不存在を確認。
- **コピードリフト検査の自動化**(`crosscheck/check-e2c6-common-data-drift.mjs` 新設):
  `search/e2c6-common-data.g` と `search/e2c6-sweep.g` の7ブロック(`BASIS21`・
  `ThetaTable21`・`SigmaTablePoly21`・`EmComponents21`・`KappaTerms`・`DThetaFormula`・
  `DSigmaFormula`)をブロック名+括弧深度で自動抽出しバイト比較。**全7ブロック
  byte-identical(ALL PASS)**。falsifier の手作業確認を恒久 fixture 化した。

### Node側(`crosscheck/check-e2c6j3.mjs`)

- `m6j3_multiplicity_table`: brute-force のみで独立再構築(λ-shortcut を信頼しない)+
  `lambda_bit_matrix`/`lambda_rank` の独立再計算・突合を追加。
- `linear_stage_empty_c6j3`(`fixture:"adversarial_unsolvable_synthetic_j3"`): 公開の
  theta_bar/sigma_bar 構造 + 同一の疑似乱数 rhs 式を独立に再構築し dual witness
  (`yM`,`yb`)を再計算・突合(実走査分は「未実行のため recheck 対象外」と明示、
  SKIP ではなく理由つきで区別)。
- `ob_synthetic_check`(G7): ObFromQPair(R=4) を独立再計算・突合。
- `periodicity_comparison_j3`(G8): EmBar15/EmC6/W を独立再計算し、証明書の
  `observed_equal` 自己申告が実際の計算と一致するかのみ検査(等号の当否は判定しない)。
- `precondition_violated_c6j3`: 構造的整形式検査のみ(本パスでは未発生 — 実走査は
  fire lock により未実行のため)。
