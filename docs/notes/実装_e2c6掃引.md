## 確定した ob 定義(裁定20)

```
ob_{6,e}(f̄) := [ q_θ(f̄) − 3⁻¹(1+θ) q_N(f̄) ]  ∈  Ob := C^θ / (1+θ)ker(𝒩_C)
```

class 6 では (1+θ)ker(𝒩_C) = (1+θ)C が証明される(委嘱16 eq 3.3・便22 eq 3.3)ため、q_N 項は
商で消え、j=2(R=Z/2)の読み出しは **ob_a = q_θ の u₄ 係数・ob_b = q_θ の u₂ 係数**(u₁+u₂+u₃
の和ではなく u₂ だけ)。平均化射影 (A) は非採用 — θ と可換しないため障害群へ落ちない
(委嘱16 §3.1 の明示反例、本実装の F1 で再現)。

## 自己発見した実装バグ 2 件(修正済み・記録として残す)

1. **M2/M3 を任意ベクトルで検査した誤り**: q_θ∈C^θ (E23a)・q_N∈C^σ (E23b) は「f̄ が線型段の
   解であること」(θ̄f̄=−f̄、𝒩̄f̄=−Ē_m)を前提とした命題であり、任意の f には成り立たない。
   最初の実装はこれを見落として EkAbar 基底ベクトルで検査し、ほぼ全数 FAIL した(数学的には
   正しい失敗 — 前提を満たさない入力への「反例」ではなく、単に前提不成立)。
   - 修正: M3(θ 側)は θ̄ が m 非依存なので、常に安全な合成系(rhs=0、
     `BuildLinearSystemC6Synthetic`)の真正な核解で広く検査。
   - M2(σ 側)は 𝒩̄f̄=−Ē_m を要求するため、実ターゲットの実 m>0 での可解性を使うと開示禁止に
     抵触する。**Ē_m(0)=0(恒等的、構造事実であって「発見」ではない)を利用し、m=0 のみで
     検査**(便2つの override 試行 — ebar=0 だけ差し替え、あるいは ebar=0+実 eps 差し替え —
     はいずれも内部無矛盾性を壊し FAIL した。両者を"同じ m の一貫した Em ペア"として使う
     必要があると判断し、m=0 に絞った)。
2. **mod R 忘れ**: q_θ・q_N は C_j = (Z/2^{j−1})^6 の元としてのみ意味を持つ(委嘱16 eq 0.5 の
   「2d=0」は R 上の恒等式であって整数上ではない)。最初の θ-不変性/σ-不変性チェックは整数の
   まま比較しており、u4 成分の符号(θ(u4)=−u4)で必ず FAIL していた。mod R=2 に還元してから
   比較するよう修正。

## ツール仕様(標準形式・第一号、2026-07-26 研究者裁定「仕様書優先」)

### search/e2c6-sweep.g

1. **入力**: `crosscheck/agree6_claude.json`(class-6 表データ、system A)のみ。ob 公式は
   `docs/manifest_e2c6_sweep_v2.md`・`docs/委嘱16_ob定義_opus_v1.md`・`sol/sol_reply_22_ob.md`
   (司令塔指定の仕様正本)から。
2. **モード**: fixture モードのみ実行(F1–F4)。実 E_m(m>0) は一切使わない — 使うのは
   (a) 合成系(rhs=0 で人為的に可解にした class-6-shaped 系)、(b) class-5 統制(独立モデル)、
   (c) m=0 の実システム(Ē_m(0)=0 が構造的に恒等ゼロであるため無害)。real-universe モード
   (`RunRealSweepC6`)は発射錠が開かない限り**呼ばれない**。
3. **出力証明書スキーマ**:
   - `linear_stage_kernel_c6`: {modulus,m,j,K_generators,K_orders,ob_a:null,ob_b:null,
     ob_mode:"PENDING",fixture} — 核のみ、ob 内容なし。
   - `ob_synthetic_check`: {fixture,R,basis_order_C6,q_theta,q_N,v,ob_a,ob_b,
     ob_mode:"quotient-ratified-v2",formula}。
   - `e2c6_real_sweep`(発射後のみ生成): {m,j,linear_solvable,witness_f_abar,q_theta,q_N,
     ob_a,ob_b,ob_mode:"quotient-ratified-v2"}。
4. **実行時不変量(M 系、委嘱16 §5 / manifest v2 F4)**: M2 (1−σ)q_N=0・M3 (1−θ)q_θ=0・M5
   (1+θ)ker(𝒩_C) の u4/u2 消滅・F4a 核enumeration の Π n_i 厳密一致。
5. **発射錠**: 冒頭で `search/FIRE_e2c6.auth` の存在とその中身が
   `docs/manifest_e2c6_sweep_v2.md` の SHA-256(`sha256sum` 経由、GAP の `Exec`)と一致するかを
   検査。一致しない限り `RunRealSweepC6` を呼ばない。認可ファイルは司令塔のみが発射時に作成。

### crosscheck/check-e2c6.mjs

1. **入力**: `crosscheck/agree6_sol2.json`(class-6 表データ、system B)+
   `certificates/e2c6/*.json` のみ。GAP コード・hall6.mjs・sol/ は不読。ob 公式は GAP 側と
   同じ 3 文書から(表データとは別枠の許可)。
2. **モード**: fixture モードの証明書のみ実際に走行中に生成されている。`e2c6_real_sweep`
   claim の証明書が将来現れても同じ照合ロジックで再検算する(fixture/real の区別なく数学は
   同じ式で再検算 — 開示是非は GAP 側の発射錠が担う領分)。
3. **出力**: 標準出力の PASS/FAIL/REJECT ログ、exit code(0=全PASS、1=いずれか FAIL/REJECT)。
4. **不変量**: (a) K_generators が宣言 fixture のシステムの mod modulus 核方程式を満たす、
   (b) 核 enumeration が全単射(|distinct|=Π orders)、(c) ob 保持証明書は証明書自身の
   q_theta/q_N から ob_a/ob_b を独立再計算し一致すること。
5. **モード錠**: ob_a または ob_b が non-null であるにもかかわらず
   `ob_mode !== "quotient-ratified-v2"` の証明書は無条件 REJECT(exit 1)。動作確認は上記
   「発射錠・モード錠の動作確認」節参照。
