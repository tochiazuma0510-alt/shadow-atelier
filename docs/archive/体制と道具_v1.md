## 検証の網(規律の心臓・ES7 の勝因)

1. **探索器と検証器の分離**: GAP が見つけたものは、独立実装(node/python)が**別経路で再計算**して初めて事実になる(`verifier/` — 既設)。ES7 の対応物: kissat の UNSAT を drat-trim が独立検証。
2. **UNKNOWN は一級の結果**。「見つからなかった」は非存在の証明ではない。timeout は判定ではない。
3. **宇宙の事前登録**: 対象(位数・生成系・列挙範囲)を計算前に固定して `provenance/LEDGER.md` に記録。後から広げる時は新しい版として。**silent cap 禁止**(範囲を絞ったら必ず明記)。
4. **主張の台帳**: 研究的結論は「主張+証拠+状態」で記録。状態語彙: verified(独立検証済み)/ candidate(片系のみ)/ UNKNOWN / refuted。**未検証の主張は台帳に入れない**。
5. **versioned 規律**: 成果物は v1, v2, … で上書きしない。配布物は bytes+SHA-256 で束縛(照合スクリプトは `atelier_lean` の manifest 検収パターンを流用)。
6. **既知例の三分**: positive control(既知の 2 冪 dihedral 例)・negative control・adversarial/edge を常備し、新しい道具はまず既知例で較正する(ES7 の「n17 較正ゲート」方式: **答えを知っている問題を先に撃たせ、通らなければ本番を撃たない**)。

## 計算工場(規模が要る時)

- **GitHub Actions = 無料計算工場**(public repo なら無制限)。shadow atlas の大規模列挙で手元が溢れたら repo 化して matrix 並列に。ES7 の実証済みパターン: SHA ゲート付き manifest 駆動 workflow・pinned ツールチェーン・成果物は bytes+SHA 束縛。
- **ES7 で流血して学んだ教訓集**(そのまま適用):
  - `.gitattributes` に `** -text`(改行正規化が SHA 束縛を壊す)
  - commit 後に `git ls-files --error-unmatch` で正本 tracked を検証してから dispatch(存在しないパス 1 つで git add 全体が fatal)
  - workflow の集計ジョブに巨大 artifact を一括 DL させない(ランナーのディスク ~85GB で死ぬ)— ログ集計方式か逐次 DL・即削除
  - ジョブの conclusion=success は「工程正常」であって数学の判定ではない — 判定は必ず成果物の中の verdict を読む
  - run 状態 queued の長期停滞と jobs API の 5xx は GitHub 側障害の症状 — 慌てて churn しない・githubstatus.com/api で裏取り
  - matrix は 256 job 上限・同時実行 ~20(超過は自動キュー)
- 16GB+ が要る単発作業は GitHub Codespaces(実証済み・実費 ~$1・手順書 `atelier_lean/ProofAtelierES5_artifacts/クラウド実行手順.md`)。

## 運営の制度(ES7 で偶発を制度化したもの)

- **毎便の目的掲示**: 作業セッションの冒頭で研究目的(sprint 計画→将来は専用の 研究目的.md)と「今日の作業が地図のどこを進めるか」を 1 行照合。目的から外れる深掘りは「ウサギ穴に入る」と宣言してから。
- **撤退条件を先に書く**(sprint に記載済み)。筋の悪い路線に固執しない・大胆に発案し軽やかに手放す。
- **双方向裏取り**: Sol を呼んだら、Sol の主張はこちらの計算で検証し、こちらの設計は Sol に反証させる(対等)。自案は「■ 新候補開示」枠で毎回さらし、証拠で殺されたら喜ぶ(ES7 先例: ArcCF・U292 再注入 — どちらも 1 便で反証され、それが制度の成功)。
- **コスト規律**: $0 の作業(GAP・ローカル計算)を先に、課金(外部モデル協議・クラウド)を絞って後に。見積もりは楽観に錨を下ろさず改装係数(文脈肥大・リトライ・積み上がり)を乗せる。
- **統計の常設**: 区切りごとに「何が効いたか」の統計を採って次の設計に還流(ES7 の `stats/campaign_stats.mjs` 方式)。

## Lean 検証基盤(ES7 の最重要資産・そのまま使える)

証明工房には **mathlib 常駐の Lean 検証サーバ**がある。初回ロード ~6 分を一度払えば、以後 **1 検証 ~0.6 秒**。ES7 幾何専用ではなく **Mathlib 全域**(FieldTheory.Galois・CategoryTheory.Galois 含む)で動く汎用資産。

- **起動**(proof-atelier 側で一度):
  ```
  cd C:\Users\81905\Desktop\proof-atelier
  $env:LEAN_PROJECT_DIR="C:\Users\81905\Desktop\atelier_lean"; npm run server
  ```
  起動時 warmUp が初回ロードを先払いする。ローカル 8GB でも常駐 2.5〜3GB で収まる(実証済み)。
- **使い方**(HTTP・どのセッションからでも):
  - `POST /api/lean-check`(body: `{code}`)— コード断片を常駐 Lean で検証(**ファイル不要**・仮想ドキュメント方式なので ES7 リポジトリを汚さない)。診断配列つき。
  - `GET /api/mathlib-search?q=` — mathlib 全宣言(約 23 万)の名前インデックス検索 = **補題名の捏造防止**。ガロア理論の補題探しにそのまま効く。
  - `POST /api/tactic-search` — ゴールを渡すと決着戦術バッテリー→`exact?`→`apply?` の順で Lean 自身に探索させる。
  - MCP 版ラッパー: `proof-atelier/server/mcp-lean.mjs`(stdio・登録すればツールとして直結)。
  - **正本マニュアル**: `proof-atelier/.claude/skills/lean-tools/SKILL.md`。
- **GT-shadows での使い所**: 有限群の関係式検証・整数行列の恒等式など decide/native_decide 向きの証明書が主戦場。大規模计算の Lean 化には ES7 の **shard パターン**(モジュール DAG + 分割 native_decide + file-scope `maxRecDepth`、雛形: `atelier_lean/ES7/` の Shard00..31 構成)が実証済みの型。公理監査(`#print axioms` — sorryAx 検出・native_decide は信頼基盤に明示)も同じ流儀で。
- **本格的な形式化フェーズに入ったら**: 専用の lake プロジェクトを新設(`lake exe cache get` で mathlib はビルドせず取得)。Mathlib 貢献(CategoryTheory.Galois 副軌道)はその先 — mathlib4 fork + 標準の開発フローで。
- 注意: atelier_lean リポジトリ(公開・ES7 キャンペーン用)に Galois のファイルを混ぜない。検証は仮想ドキュメントで足り、恒久ファイルは専用プロジェクトへ。
