## I-15.【夢級・NO 方向】欠損因子 D — 井原が外れる世界の完全座標系と「fake は必ず並進型」

**種(予想+構成・出所 = N∞ 哨戒線解錠という工程の観察)**: 哨戒線は「fake 1 件で G_ℚ ⊊ ĜT 確定」の NO 方向装置として立った。だが **NO 世界の地図**はまだない — fake が出たとき「どれだけ外れているか」を測る座標系を先に作る。GT^odd ≅ Aff(Ẑ^odd)×C₂(便 75 F6.2)の座標で、Im(Ih^odd) は線形部×C₂ へは全射(χ_cyc の odd 部+χ₄ — 正典既用の古典事実)。すると問いは「**線形部に全射な Aff(Ẑ^odd)×C₂ の閉部分群の分類**」に落ち、私の机上計算では:

1. 並進部との交差 T は単元倍で安定な閉部分加群 = **閉イデアル ∏_p p^{k_p}Ẑ_p**(単元差の稠密性の一行)。
2. 剰余の割れ目は H¹((Ẑ^odd)^×, Ẑ^odd/T) に住むが、**2 が odd 側では単元**なので中心元 2 の (2−1)=1 可逆性で **H¹ = 0**(C₂ 側は Hom(C₂, pro-odd) = 0)。
3. よって並進共役を除いて **Im(Ih^odd) = (∏_p p^{k_p}Ẑ_p) ⋊ ((Ẑ^odd)^× × C₂)** — **NO 世界は超自然数 D = ∏ p^{k_p} 一個で完全に符号化**され、D = 1 ⟺ odd Conj 5.1。各 k_p は有限段の深さ欠損(ord(a_{p^m}) 列)として測定可能。

帰結の設計(どちらの世界でも同じ対象を測る): **YES 世界 = 「D = 1 の証明」・NO 世界 = 「D の最初の非自明座標 (p, k_p) の決定」** — 哨戒線の deliverable を「fake の有無」から「D の座標」へ格上げする。さらに分類の系(candidate): **fake が存在するなら並進型 fake(u ≡ 1・ε = 0 の shadow)が素数冪窓に存在する** — 哨戒述語を並進 fiber に特化してよく、探索空間が |GT| から n へ落ちる。おまけの観察: H¹ を消す中心単元も、I-11 の普遍 radical も同じ **2**(odd 世界で 2 は「単元かつ radical」という二重の特権を持つ)— 偶然かどうかは分からないが、記録する。

**何が新しいか(grep 済)**: N∞ の NO 方向は「fake 1 件で確定」の判定文まで(哨戒線の実装解錠)。**閉部分群の分類・欠損超自然数 D・H¹ 消滅論法・「fake ⟹ 並進型」の系・両世界同一 deliverable 設計は未出**(grep: 「超自然数」「並進型」「閉部分群の分類」該当なし)。ラベル: **F6.2 の系としての NO 世界設計**。

**検証の一手目**: (a) 数学者に分類の 1 頁化(閉イデアル補題+H¹ 消滅+並進共役の吸収 — 全部で 1 頁の見込み・外部文献不要)。(b) falsifier に前提の突き崩し: 「線形部×C₂ への全射」は各有限段の座標同定(u = χ mod n・ε = χ mod 4)に依存 — 基点規約でこの同定が捻れる筋があるか。(c) 司令塔判断で、哨戒述語の並進 fiber 特化(u ≡ 1 shadow の非実現判定)を N∞ 実装 scope の**将来拡張候補**として台帳登録(現 receipt の scope 外 — F8.5 の NEW RECEIPT REQUIRED に該当・今は登録のみ)。

**破綻しそうな点**: 分類は GT^odd の**直積構造**(C₂ が並進に作用しない・reduction が C₂ を捻らない = F6.2(b))に全面依存 — ここが段ごとに捻れる修正が入ると H¹ の係数が変わり、D 一個では済まなくなる(その場合は「D+捻れ類」の二座標へ後退)。「fake ⟹ 並進型」は逆極限水準の言明で、**特定の有限窓の fake がその窓で並進型とは限らない**(下段へ射影して初めて並進型が現れる)— 哨戒特化を有限段に降ろすときの言い換えで誇張が入りやすい(falsifier 検分要)。また「両世界同一 deliverable」は美しいが、D ≠ 1 の測定は深さ欠損の実測 = 封印線の向こうの作業であり、設計だけが先行して測れない期間が長い。

## I-16.【現在線級・工程の数学化】捻れ関手カタログ — バグ = 意図した関手の捻れ、事故署名の事前表

**種(工程翻訳・出所 = 18/108 事故と「section 産物」撤回という二つの事故の観察)**: 今日の k9 事故(共役順序の反転 → 対称な保存量 m+m′=17 → 生存 18 件)と W3-10 の「13 系非零 = section 産物」(裁定 21 撤回)は同じ型: **実装事故は「意図した関手 F の代わりに捻れ版 F^tw を計算する」ことであり、事故出力は F^tw の固定点集合/artefact として完全に予言できる**(oddH §11.4 は op-捻れの生存条件 u ≡ ±(1+2ϰ) から 18 = 2·9 を閉形式で再現した)。★75-1「対称な誤答は強い」を規範から装備に変える:

3. **数学としての面**: 「どの捻れが目に見える artefact を残すか」は作用の対称性の問題(op-捻れの固定点 = 実質的に反転で閉じる shadow の集合)であり、署名の閉形式自体が小さい補題群になる — 事故対策が同時に作用の構造理解になる、という一石二鳥を狙う。

**何が新しいか(grep 済)**: 個別事故の解剖は §11.4(op-捻れ・完全再現)と裁定 21(section 産物)に既出・★75-1 は教材(規範)。**類型のカタログ化・署名の事前表・schema 編入・署名閉形式の補題化は未出**(grep: 「bug_signature」「捻れ関手」「固定点集合」該当なし)。ラベル: **§11.4+★75-1 の装備化**。

**検証の一手目**: (a) implementer に予言の追試(n=5,7,11 の op-捻れ生存数 = 2n を GAP で確認 — 既存 family-window 装置の流用で分単位)。(b) falsifier にカタログの初版起草(T1–T5 の各 artefact 署名の導出 — 導出できない類型は「署名なし = 事前表で守れない」と正直に記録)。(c) ops で cert schema 次版に `bug_signature_table` 欄(optional)の追加提案。

**破綻しそうな点**: カタログが小さすぎて実際の次の事故は表外から来る(事前表は「既知の敵」しか守れない — それでも再発だけは全滅させられる、が売り)。署名の一致は偶然でも起きる(正しい観測値がたまたま 2n になる窓はある)— 警報を判定と混同すると偽陽性で工程が重くなるため、「警報 = 監査起動」の規約を崩さないことが必須。署名の閉形式が出ない捻れ(非単射系は入力依存)では表が書けず、カタログの半分は「型名だけの注意書き」に留まる可能性。
