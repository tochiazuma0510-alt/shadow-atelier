## 4. Checkpoint and resume contract

Logical candidate/fibre work is chunked at at most 256 attempts.  A sealed
v3 checkpoint is produced at safe chunk/rank/terminal/resource boundaries.
Every epoch binds input, target, normalized callsites/digest, and dual
digests.  The canonical row cursor may cross only complete weighted rows; a
stored row is checked for formula digest, `K`, `W`, Delta order, all ten
kernel orders, support/kernel/global cursor bounds, and contiguous complete
state.  K=0 cursor checks remain coordinate-specific when runtime data is
available.  An interrupted suffix is metadata only: the serialized state is
the last safe complete chunk and explicitly records the repeat interval.

Resume accepts only a sealed v3 checkpoint with the exact semantic/cache
contract.  All stored columns and provenance are authenticated, then a fresh
v1 echelon is rebuilt from rank zero.  Stored pivots, reduced target, and
cache state are discarded; the fresh dual is derived and the safe complete
boundary/correction progress is retained only when its dual digest and
complete-chunk contract match.  The actual v1 loader then revalidates every
retained weighted formula against that fresh dual.  Any partial/repeated
suffix is removed from semantic progress (its typed history is retained only
for audit/counter accounting), while the safe prefix/cursors remain.  Nonzero remainders
derive the current exact dual; zero remainders reject stale dual fields.
