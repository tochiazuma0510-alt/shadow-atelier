## Confirmed v1 defects to remove

These are audit findings, not optional suggestions.

1. PB4's old `A12` Fox row used prefixes beginning with `h*A12*r^-1`.
   With

   ```text
   A12 = z*r^-1*q^-1*p^-1*c^-1*b^-1,
   ```

   the six terms must have prefixes

   ```text
   h,
   h*z*r^-1,
   h*z*r^-1*q^-1,
   h*z*r^-1*q^-1*p^-1,
   h*z*r^-1*q^-1*p^-1*c^-1,
   h*z*r^-1*q^-1*p^-1*c^-1*b^-1
   ```

   in the `z,r,q,p,c,b` coordinates with signs `+,-,-,-,-,-`, as in
   v402 (2.2).  Use the literal `z`, never `A12`, in those prefixes.

2. Production used `tau=sum(all central coefficients)`.  This is the wrong
   quotient coordinate.  After the constructive central elimination, use

   ```text
   tau = sum_{h0 in H0} Z'(h0*z^2)
   ```

   modulo 3, exactly as v401/v402.  A constant central orbit vector is a
   mandatory canary: the erroneous all-coordinate sum is zero in
   characteristic three, while the retained `z^2` coordinate is nonzero.

3. PB4 orbit representatives must be the canonical `H0=ker(kappa)`
   representatives determined by the first authenticated PC coordinate:
   for every support value compute `j=kappa(h)` and `h0=h*z^(-j)`, then
   require `kappa(h0)=0` and `h=h0*z^j`.  A lexicographic central-orbit
   transversal is not a substitute here.  Central-power translates must
   yield the same `h0` action translation.

4. v1 never ran the six PB4 action families: it inserted only the 44
   identity-conjugator correction columns and then stopped.  Implement the
   actual support-hitting positive-first oracle for exactly the six action
   relators of v402 (1.4), translated by canonical elements of `H0`.  The

   Do not reintroduce the old 11-family closure.

5. The correction schedule must enumerate/resume actual compact

6. v1 checkpoints saved only a cursor and rank although the loader expected
