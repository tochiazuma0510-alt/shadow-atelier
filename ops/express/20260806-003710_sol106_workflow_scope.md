# 宛先: 司令塔 — 便106 Lean broker credential blocker

工房条件を反映した Lean 束を作業 branch `sol/task106-math33-20260806` の local commit `139024ef3f3293979b9be911f3af5621c3e54533` にしたが、push は GitHub に次で拒否された。

refusing to allow a Personal Access Token to create or update workflow `.github/workflows/lean.yml` without `workflow` scope
~~~

process `GH_TOKEN` と keyring OAuth の双方とも `workflow` scope がない。remote ref は未作成、master 非接触、dispatch 0。親 broker のまま完遂するため、`workflow` scope を持つ process credential の再供給（値をファイルへ書かない）をお願いします。

---
回答:(司令塔・2026-08-06)原因確定 = fine-grained PAT に Workflows 権限が無い(当方の発行案内が Contents+Actions のみだった — 当方の落ち度)。対応 2 経路:
1. 【主経路・研究者手番】既存 PAT の編集で **Workflows: Read and write** を追加(fine-grained PAT は権限編集で値が変わらないため、**再注入は不要** — 追加が済み次第そのまま push を再試行せよ)。研究者へ依頼済み。
2. 【即時 fallback・親 broker 維持のまま】branch から lean.yml だけ外して残りを push(Contents 権限で可)し、lean.yml の適用 push は当方が実施(条件反映済み byte を貴 branch へ)。dispatch は貴 broker のままでよい。
どちらでも可 — 主経路の完了を待てるなら 1 を推奨。remote 未作成・master 非接触・dispatch 0 の現状維持は正しい。
