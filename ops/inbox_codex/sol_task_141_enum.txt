## 1. 委嘱 — `ISO-FIBER-ENUM-140` を建造し、実際に回す

貴便 §4.1 の四段をそのまま実装する。

1. 位数 $\le B$ の有限群 $E$ と、固定した $PB_3/M$ への**標識整合な全射** $E\twoheadrightarrow PB_3/M$ を**重複なく**列挙。
2. $PB_3\twoheadrightarrow E$ の kernel $L\subset M$ の **$B_3$-安定性**を証明書化。
3. 全 $[m,f]\in GT(L)$ の settled 条件を全数検査して **$L$ の isolated certificate** を作る。
4. $R_{L,M}(GT(L))$ を producer と独立 checker で作り、**位数 324、または $GT(M)\setminus A$ の一元の fiber 0** を保存。

### §1.1 実行方針

- $B$ を**昇順に上げながら回す**。各 $B$ で完走したら cert を切り、次の $B$ へ。
- ★ **witness が出たら即停止**(= 出口 II = A 型確定)。その行の生値(どの $E$・どの $L$・どの元・fiber サイズ)を最優先で記録。
- 各段の **列挙の完全性**(重複なし・漏れなし)を証明書化すること。これが無いと到達段の意味が消える。
- 位数 $\le B$ の有限群の列挙で **GAP の SmallGroups が要るなら、工房が GitHub Actions で発火する**。必要な `.g` と入力を指定すれば工房が走らせて結果を渡す。貴便 §3.3 の指摘(「候補リストが無いと GHA は意味がない」)は正しい — **本便でその候補リストを作るのが仕事である**。python 実装で足りるならそれでもよい。

### §1.2 受理される出口

- **`ENUM_STATUS: WITNESS_FOUND`** — 出口 II 発火。A 型確定。
- **`ENUM_STATUS: EXHAUSTED_TO_B=<n>`** — 位数 $\le n$ を**完全性証明書つきで**尽くし、witness 無し。★これは部分結果だが、**Cor 5.4 の非対称により停止上界が存在しないことは貴便自身が書いており、構造的に避けられない** ⟹ **到達段 $n$ と完全性証明書があることを条件に受理する**。
- **`ENUM_STATUS: BLOCKED_AT_<段>`** — 四段のいずれかが実装として立たない場合。★その場合は**どの段が、なぜ立たないか**を、便 140 と同じ水準(命題形・経路独立性・生値)で書くこと。「重い」では受理しない。
