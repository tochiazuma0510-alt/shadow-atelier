## §1 ★ 規約宣言(WDICT-5 の教訓 — **コードを 1 行書く前に凍結**)

### 1.1 三つ組の向き — ★ **反転だけでは翻訳が決まらない**

| | 関係式 |
|---|---|
| **工房** | $x\,y\,z=1$($x,y,z$ = $0,1,\infty$ のまわりのループ・$z=(xy)^{-1}$) |
| **KMSV** | $\sigma_\infty\,\sigma_1\,\sigma_0=1$(**逆順**・判明済) |

> ### ⚠⚠ CV-9 危険点
> 「逆順」と分かっても翻訳は**一意に決まらない**。少なくとも 2 つの正しい候補がある:
> $$\textbf{(T-a)}\ (\sigma_0,\sigma_1,\sigma_\infty):=(z,\,y,\,x)\ \Longrightarrow\ \sigma_\infty\sigma_1\sigma_0=x\,y\,z=1\ \checkmark$$
> $$\textbf{(T-b)}\ (\sigma_0,\sigma_1,\sigma_\infty):=(x^{-1},\,y^{-1},\,z^{-1})\ \Longrightarrow\ \sigma_\infty\sigma_1\sigma_0=(xyz)^{-1}=1\ \checkmark$$
> **(T-a) と (T-b) は別物**(前者は分岐点の役割を入替え、後者は局所モノドロミーを反転する)。**どちらが正しいかは、どの分岐点を「0」と呼ぶかの規約に依存し、群論だけでは決まらない。**
>
> **⟹ PILOT の第一級の成果物は「どちらが正しいか」の決着である。**
> pilot は**答えが既知**(LMFDB 公開値)なので、**(T-a)(T-b) を両方走らせ、公開値を再現する方を採る**。さらに $(\sigma_0,\sigma_1)$ の 6 通りの順序割当も併せて全数試すこと(passport $7.1.1/2.2.2.2.1/3.3.3$ は**三成分の cycle type が相異なる**ので、ここは cycle type で絞れる — 我々の本番 $[9,9,9]$ とは違い pilot は楽)。
> **⟹ 本番(種数 4・passport $[9,9,9]$・三成分が同型)では cycle type で絞れないので、pilot で確定した翻訳規約が本番の唯一の頼りになる。これが pilot の最大の価値。**

**receipt 欄**: `triple_convention` ∈ {`"T-a"`, `"T-b"`}、`branch_assignment`(6 通りのどれか)、`decided_by`: `"pilot reproduction of LMFDB published map"`。

### 1.2 作用の左右・置換の合成順

- `coset_action` ∈ {`"right"`, `"left"`}: $\Delta$ が $\Gamma\backslash\Delta$ に右から作用するか左からか。
- `perm_compose` ∈ {`"left_to_right"`, `"right_to_left"`}: $(\alpha\beta)(i)=\beta(\alpha(i))$ か $\alpha(\beta(i))$ か。
- **assert**: 実装した合成で $\sigma_\infty\sigma_1\sigma_0=\mathrm{id}$ が成り立つこと(成り立たなければ規約不一致 ⟹ **即停止**)。
- ⚠ Julia の `Permutation`/`perm` 型と GAP の規約は**一致しない可能性**がある。GAP は $i^{\alpha\beta}=(i^\alpha)^\beta$(左から右)。**GAP 側で生成した三つ組を Julia へ渡す際は必ず往復テスト**(GAP → JSON → Julia → 合成 → GAP へ戻して一致)を通すこと。

### 1.3 級数の変数規約

- `series_variable`: 展開点 $p\in\mathcal H$ における**円板座標** $w=\dfrac{z-p}{z-\bar p}$(三角群は余コンパクトなので $q$-展開ではない)。

- `series_precision`: 打ち切り次数 $N$ と作業精度(桁)。
- **assert**: $|w(p)|=0$、$|w(z)|<1$ for all $z\in\mathcal H$。

### 1.4 その他

- `normalization`: §4.5 の Möbius 吸収規約(**計算前に固定**)。
- `field_of_moduli`: pilot は $\mathbb Q$(公開値)。

> ### ★ SVD 回避(重要な設計判断)
> **Arb/Nemo に SVD は無い。**しかし**必要ない**: 求めるカーネルは(rigid ゆえ)**次元 1** が期待値なので、**未知数の 1 つを 1 に固定して正方系を `approx_solve` で解く**のが標準手法。
> **ゲート**: 解いた後に**残差**と、固定した未知数を別のものに替えたときの**解の一致**を確認する(次元 1 の実証)。次元が 2 以上なら固定の取り替えで解が変わる ⟹ **検出できる**。
> ⟹ **FLINT の別途リンクは pilot では不要**(Nemo が FLINT/Arb を同梱)。本番(種数 4)で条件数が悪化した場合に初めて C ソルバーのリンクを検討する — **C 拡張は CAS 中立なので後付け可能**(survey §7)。

### 3.4 Newton 精密化の扱い

KMSV の genus 0 既定は `Al:="Newton"`(survey §3.1 L107)。**pilot では初手で省く**:
- 省く理由: 移植対象を最小化し、**まず粗い精度で end-to-end を通す**ことが pilot の目的。
- 追加する条件: L7 の認識が精度不足で失敗する場合のみ。**その場合でも第一手は「作業精度を上げて再実行」**(survey §8.1 の Ex 5.27 方式と同じ)。

### G-5 ★ 最終方程式 vs LMFDB 公開値 — **Möbius 差の吸収規約(計算前に固定)**
種数 0 の Belyi 写像は**始域の Möbius 変換の分だけ不定**。よって**直接の係数比較は無効**。

**規約 N(採用)**: **正規化を先に決めず、事後に Möbius を探す。**
```
1. 我々の phi と LMFDB の phi_L の、0/1/infinity 上の分岐点を重複度つきで列挙。
2. 重複度の一致する点どうしの対応を全数列挙し、各 3 点対応から Mobius mu を構成。
3. phi_ours ∘ mu == phi_L となる mu が「ちょうど 1 つ」存在することを要求。
   [G5-a] 存在する           [G5-b] 一意である
```
**なぜ規約 N か**: 事前正規化(例「$e=7$ の点 → $x=0$、$e=1$ の点 over 1 → $x=1$、$e=3$ の点の 1 つ → $x=\infty$」)は、**最後の 3 択が残る**(∞ 上の 3 点は対等)。事後探索なら**その 3 択も探索に含めて一意性を確認できる** ⟹ **より強いゲート**。
- 参考: 本 passport は $e=7$(over 0)と $e=1$(over 1)がそれぞれ**一意**なので、事前正規化を併用してもよい(探索空間が 3 通りに減る)。**併用する場合も [G5-b] の一意性確認は外さないこと。**

## §8 独立オラクル(推奨・任意)

pilot は**次数 9・種数 0** なので、**代数的(Gröbner)経路が現実的**: $P,Q,R$ の未定係数に $P-Q=cR$ と重複度条件を課した多項式系を解く。これは**数値経路とは完全に独立**であり、**第二系統として G-5/G-6 を裏取りできる**。

> ⚠ **ただし pilot の主目的は数値層の移植検証**である。**代数経路で「答えが出た」ことを pilot 成功と読んではならない** — 本番(種数 4)で使えるのは数値経路だけであり、代数経路は本番に**移送できない**(survey §8.1 の次元勘定より、種数 4 では Gröbner が爆発する)。
> ⟹ **代数オラクルは「較正の正解データ」としてのみ使う。**
