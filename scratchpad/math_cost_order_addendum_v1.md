## 0. 判定(先出し)

**(A) 「層 i の再認証 = c0 + c1·R_i」の c1 は、コード上 Theta(k_par · R_i) で確定する。** falsifier の Theta(k·R_i) 表記は**正しい**。ただし決定的な但し書きが 1 つ抜けている: **この k は「その層を作った run の k」(歴史的に 128)であって「現 run の k」ではない。** 現 run の k を上げれば、その run が作る層は将来 k' 行の層として再認証され、層費用は k' に比例して上がる。**回転で k を上げる逃げ道は、この自己参照で目減りする。**

**(B) c1 の由来は「全 R_i 行への native pairing」でも「行 bytes の再 hash」でも「metadata の型検査」でもない。** 実体は **親の各候補が持つ Theta(R_i) サイズの JSON 2 本(`reduction.json` / `physical-literal.json`)の parse・再直列化(canonical)・sha256 の往復**である(P6 `:1874-1930`, `:1709-1731`, `:643-646`, `:632-637`)。
私は artifact の中央ディレクトリからこの 2 本の実バイト量を**全数実測**した(下表)。層あたり **129.78 / 141.43 / 153.19 MB**、単位 R あたり **91,433 B**。時間と突き合わせると **0.0853 s/MB**。
**⇒ falsifier の「per-byte モデルは 53 倍外れ」は結論としては正しいが、理由の記述は要修正**: 費用は依然 byte 比例である。ただし「envelope 全体の byte」(sha256 のみ・0.00223 s/MB)ではなく「parse される Theta(R) JSON の byte」(0.0853 s/MB)であり、**同じ 1 byte に 38.2 倍の単価差がある**。この区別が設計上いちばん効く。

**(C) 積み上げ壁は n について 2 次。** T_P(n) = 1580.7 + 46.68·n + **0.568·n^2** s(k=128・係数導出は §2)。cap 5,400 s に達するのは **n ≈ 50.3・rank ≈ 7,900**。**falsifier の n ≤ 86.8 / rank 12,586 は、線形 n モデルゆえ楽観側に外れている**(n=86.8 では 2 次項だけで 4,283 s)。撤回すべきではないが、**より手前で詰む**と訂正すべき。

**(D) 回転の k_max は ≈ 250 ではなく ≈ 211**(n=2・R=48,384)。falsifier は層費用を k=128 のまま据え置いて現 run の k だけ上げたため過大。**「140〜360 run 級」は正しい括り**で、内訳は **137 run(冷保存・k を cap 上限まで)/ 167 run(n=2 回転・k 上限)/ 367 run(k=128 据え置き)**。

うち **p1 補正相だけで 7.93 s/行 × 46,934 行 = 372,356 s = 103 時間**。**律速は Theta(k·R) ではなく「1 行あたり R 非依存の 12 s」である。** checker を含めると 1.2 倍として **≈ 450 時間**。**run 数は最良でも 137。**

### 1.4 Theta(R_i) か Theta(k·R_i) か — 判定

**Theta(k_par·R_i) で確定。コードが決める。** 3 点(k_par = 128 固定)では分離できないという falsifier の認識は正しく、**分離はコードで済む**: 上記 #1–#6 はすべて 128 回の候補ループの内側にあり、1 候補あたりちょうど `R_i + ordinal` 要素を触る(`:1927` が `len(reduction["ordered_reductions"]) == 1450 + ordinal` を**総当たりで要求**しているので、これは推測ではない)。

**falsifier の Theta(k·R_i) 表記は妥当。** ただし次の 2 点を明記しないと設計判断を誤る:

1. **k は親の k**。c1 = gamma·k_par、gamma = 6.0911e-5 s/(候補×行)。現 run の k を K に上げると、その run が作る層の再認証は **gamma(K·R + K(K-1)/2)**、つまり **K に比例**(かつ K^2 の小項つき)。§3 で効いてくる。
2. **定数側 c0 ≈ 20.0 s も Theta(k_par)**。内訳は候補あたり **(20.044 - gamma·8128)/128 = 0.1527 s** — witness/oracle-view/6 phase manifest/row-manifest/instruction/target/candidate-manifest の小 JSON 約 15 本の parse+canonical+seal と file_pin 約 15 本。**k を上げれば c0 も比例して上がる。**

### 1.5 falsifier の per-byte 棄却の評価

- 「per-byte モデル(0.118 s/MB)は 53 倍外れ、実測 0.00223 s/MB」: **正しい**が、比較している byte が違う。0.00223 s/MB は **A_i(envelope 全 file の sha256)** の単価。層の再認証本体は **0.0853 s/MB**(私の実測)で、**両者の比は 38.2 倍**。
- したがって正しい言い方は「層費用は byte 比例ではない」ではなく **「envelope の byte ではなく parse される Theta(R) JSON の byte に比例する。単価は 38 倍違う」**。
- この訂正は実務的に大きい: **envelope を小さくしても効かないが、Theta(R) JSON を小さくすれば直に効く**(§6)。

## 2. 審査項目 2 — 積み上げ壁の次数と係数

### 2.1 T(n) の形

R_i = R0 + k(i-1)(R0 = 1450・k = 128)として

  Sum_{i=1}^{n} (c0 + c1·R_i) = **n·c0 + gamma·k·n·R0 + gamma·k^2·n(n-1)/2**

すなわち **層再認証の総和は n の 2 次**、2 次係数は **gamma·k^2/2 = c1·k/2**。
加えて現 run の候補相も R = R0 + kn とともに増えるので **+ b_cand·k^2·n**(1 次)。

**T_P(k,n,R) = f0 + f1·k + (selection+separator) + k(a_cand + b_cand(R + k/2)) + Sum_i L(R_i)**

| 記号 | 値 | 出所 |
|---|---:|---|
| f0 + f1·k(P 残差の n=0 部) | 26.01 + 1.2734k | v1/v2/v3 の P 残差 68.670/104.647/189.963 の LS(残差 <= 2.9 s) |
| selection + separator | 13.1 | v6 実測 11.948 + 1.165 |
| a_cand(候補あたり R 非依存) | **10.77 s** | 六相 11.058 - 消去相の R 比例分 0.275 |
| b_cand(候補×行) | **1.45e-4 s** | v5→v6 の消去相増分 2.302 s /(128×127.5)=1.410e-4、v6 平均 1.507e-4 の中間 |
| L(R)(P 側 層計・計器) | **22.17 + 0.008883R** | 35.079/36.131/37.353 の LS(残差 <= 0.057 s) |
| 未計器の層あたり影 | **+9.82 s** | run 間限界 43.78/45.04/49.21 - 計器 = 8.70/8.91/11.85 の平均 |
| **L_eff(R)** | **31.99 + 0.008883R** | 上 2 行 |

**v6 での検算**: 26.01 + 163.0 + 13.1 + 128×(10.77 + 1.45e-4×1898) + Sum(31.99 + 0.008883×{1450,1578,1706}) = 202.1 + 1413.8 + 138.0 = **1,753.9 s**(実測 1,755.57 s・**誤差 0.1 %**)。部品は独立に較正しているので、これは自明な一致ではない。

### 2.2 cap への到達点

k = 128 固定で n を増やすと

  **T_P(n) = 1,580.7 + 46.68·n + 0.5685·n^2**  (s)

| n | rank | T_P |
|---:|---:|---:|
| 3 | 1,834 | 1,754 |
| 20 | 4,010 | 2,770 |
| 40 | 6,570 | 4,386 |
| **50.3** | **7,894** | **5,400 = cap** |
| 60 | 9,130 | 6,456 |

**⇒ 積み上げの cap 到達は n ≈ 50.3・rank ≈ 7,900**(目標 48,384 の **16.3 %**)。

**falsifier の n <= 86.8 / rank 12,586 との差**: 彼のモデル `producer(k,n) = 33.93 + 12.4046k + 43.520n` は **n について線形**で、(i) 層再認証の Sum c1·R_i が n^2 であること、(ii) 現 run の消去相が R = R0+128n とともに増えること(+2.38 s/n)を吸収できない。n = 86.8 では 2 次項だけで 0.5685 × 86.8^2 = **4,283 s** になり、線形外挿は成立しない。**F-v6-1 の「壁は残り悪化」は正しいが、悪化の度合いは彼の見積りよりさらに大きい。**

## 3. 審査項目 3 — 回転の逃げ道の棄却の妥当性

### 3.1 定常状態のモデル

n 層を保持したまま回転し、現 run の大きさを K にする。**将来の層はすべて K 行の層になる**ので

  T_P(K, n, R) = [f0 + sel + n(A + F + 影)] + K·[f1 + a_cand + n·0.1527] + K·R·[b_cand + n·gamma] + (K^2/2)·[b_cand + n·gamma]

(A ≈ 3.0 s = envelope hash・F ≈ 0.9 s = state-restore+pairing・影 ≈ 9.8 s)

R = 48,384 での候補あたり単価と k_max:

| n | R 非依存部 | Theta(k·R) 部 | 候補あたり計 | **k_max** | T_P(k=128) |
|---:|---:|---:|---:|---:|---:|
| 0(冷保存) | 12.043 | 7.016 | 19.059 | **281** | 2,480 s |
| 1 | 12.200 | 9.963 | 22.163 | **241** | 2,891 s |
| **2(回転)** | 12.357 | 12.910 | 25.267 | **211** | **3,303 s** |
| 3(現行) | 12.514 | 15.857 | 28.371 | **187** | 3,715 s |

- **falsifier の「n=2 で producer ≈ 3,200 s(k=128)」は私の 3,303 s と一致**(誤差 3 %)。この部分の外挿は妥当。
- **k_max ≈ 250 は過大。正しくは ≈ 211。** 差の理由は §1.4-1: 彼は層費用を k=128 で固定したまま現 run の k だけ 250 に上げた。K=250 の run が作る層は 250 行の層になり、その再認証は **gamma·250·48,384 = 736 s/層**(k=128 なら 377 s/層)。この自己参照を入れると k_max は 211 に落ちる。
- 「層あたり 397 s(R=48,384)」= 20.044 + 0.0077966×48,384 = **397.3 s** — 検算一致。ただし**これは k_par=128 の層の値**であることを明記すべき。

### 3.2 「140〜360 run 級」の根拠

登坂に必要な run 数は N = Integral_{R0}^{R_max} dR / k(R)。k を各 rank で cap 上限に取ると

  **N(n) = [A(n)(R_max-R0) + B(n)(R_max^2-R0^2)/2] / (5400 - C0(n))**
  A(n) = 12.043 + 0.157n、B(n) = 1.45e-4 + 6.0911e-5·n

| 戦略 | run 数 | producer 総時間 |
|---|---:|---:|
| 冷保存 n=0・k を cap 上限 | **137.1** | 740,177 s = **205.6 h** |
| 回転 n=1・k を cap 上限 | 152.1 | 821,454 s = 228.2 h |
| **回転 n=2・k を cap 上限** | **167.2** | 903,149 s = **250.9 h** |
| 回転 n=3・k を cap 上限 | 182.5 | 985,266 s = 273.7 h |
| **k = 128 据え置き(n によらず)** | **366.7** | 749,593〜1,001,038 s = 208〜278 h |

**⇒ falsifier の「140〜360 run 級」は正しい括り**であり、内訳は「k を上げられるだけ上げれば 137〜183、k=128 のままなら 367」。**上端 360 は「k を上げない」場合であって、上げられないからではない。**

### 3.3 線形外挿の限界(明記すべき制限)

1. **係数の R 依存**: b_cand = 1.45e-4 は R ≈ 1,900 での実測。消去相は「numpy の実消去 Theta(R·48,384)」+「Theta(R) の JSON 直列化」の混合で、前者の単価は R によらないが後者は cache/GC の効きで変わりうる。R が 25 倍になったときに単価が同じである保証はない。
2. **gamma = 6.0911e-5 は 3 点・17 % の R 範囲からの外挿**。E の梃子比が 5.9 倍なので、0.1 s の系統誤差が gamma を 10 % 動かす(私は増分から 5.41e-5 と 6.77e-5、**幅 22 %** を得た)。R = 48,384 への外挿はこの幅が 26 倍に増幅される(層あたり 353〜438 s)。
3. **runner 差**: GHA の shared runner は同一 workflow でも 1.5 倍程度ばらつく。run 間限界の 2 階差 +4.16 s はこの帯に入る。
4. **交絡の未分離**: 各 run で版が変わっている(authenticator 追加・acceptance +2.31 MB・計器 +6.13 MB)。「n を 1 増やす」と「版を 1 つ進める」が完全に共線。
5. **cap 以外の壁を含んでいない**: メモリ(§7)・artifact サイズ(§6)・GHA job の 6 時間制限。

**⇒ §3.1/§3.2 は「診断」であり gate でも定理でもない(裁定 2225)。ただし §4 の下界は外挿を使わない部分を含む。**

## 9. 進言(司令塔向け・優先順)

1. **【最優先・費用ゼロ・意味論に触れない】Theta(k·R) payload の圧縮**(§6)。`ordered_reductions` / `physical_factors` を `coefficients.u8` + run あたり 1 本の行毎定数表に置き換える。**642:1**。証拠命題は 1 つも落ちない。冷保存と独立・併用可。**Sol への設計依頼に値する最大の一手。**

4. **【計器】層の native-metadata 区間に「parse した Theta(R) JSON の総バイト」を追加**(falsifier の要求 2 より安く強い。私の外部測定 129.78/141.43/153.19 MB と突合できる)。
