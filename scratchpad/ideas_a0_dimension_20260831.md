## 札 1: 終端 rank の加群論的上界 r_max — 「closure は終わるのか」を orbit 計算で一発回答

- **種**: 装置提案(+構成)。規模: 現在線級。出所: ℤ/3[G]-加群の一般論からの必然。
- **機構の芯**: closure が張る空間 V は「44 seed の translated copy の張る空間」であり、
  translation が固定群 Ḡ(キー空間に作用する関与有限商、と仮定)から来るなら V は
  ℤ/3[Ḡ]-部分加群。ゆえに r = dim V ≤ Σ_{s∈44seeds} |Ḡ·s|(orbit サイズの和)。
  orbit サイズは closure を回さず stabilizer 計算(|Ḡ|/|Stab(s)|)で出る — GAP の得意分野
  (棚: twistedconjugacy 等)。Ḡ が 3 群なら augmentation filtration による精密化
  (dim ℤ/3[Ḡ]·s は s の深さで急減)も取れる。r_max が予算内(10^4〜10^5)なら
  closure 完走は保証つき GO、10^8 級なら closure 路線 NO-GO の裁定材料。
- **なぜ効くか**: 現況⑥「最終 rank r 未知 ⟹ 完了率が原理的に言えない」を直接殺す。
  frontier 1,132 増加中という不安が「上界 r_max のどの辺りか」という座標に変わる。
- **費用と最初の 1 実験**: Sol へ 1 問(下記)→ 44 seed 代表元を受け取り GAP で orbit
  サイズ 44 個を計算(数分〜1 時間級)。1 便で GO/NO-GO。
- **既試行との差分**: 3 系統も新路線も「走って測る」方式。上界を先に宣言した形跡は
  こちらから確認できない(不明のまま書く)。
- **破綻しそうな点**: (i) translation 群が有限商でなくキー空間が実質無限なら上界は出ない
  — ただしその判明自体が「closure 完走路線は原理的に終わらない」という決定的裁定になる。
  (ii) 生成規則が translation だけでなく seed 同士の乗法を含むなら上界式が変わる。
- **Sol に確認する 1 問**: 親→子の生成規則は固定群 Ḡ の translation 作用のみか、
  新しい乗法(seed 積・交換子)を含むか。Ḡ は有限か、位数はいくつか。

## 札 3: 深さ障壁の恒久 negative 証明書 — 「残差の頭は今後のどの行にも消せない」を次数で言う

- **種**: 構成(証明書)。規模: 現在線級。出所: filtered algebra の一般論からの翻訳。
- **機構の芯**: probe 陰性時の残差 w(target を rank-R 基底で reduce した残り)の台を取る。
  キー空間に深さ δ(Jennings/中心列次数・または seed からの生成距離)が定義でき、
  生成規則が深さ非減少(子行の台の最小深さ ≥ 親のそれ、と仮定)なら、
  frontier 全親の最小深さ d_F と残差の最浅キー深さ d_w の比較で
  d_w < d_F ⟹ 以後どの行も w の頭に触れない ⟹ この closure での membership は
  **完走なしで恒久 negative 確定**。完全確定に届かなくても「残差の浅い部分
  nnz(w ∩ depth < d_F)」は単調不変量になり、負区間 1,316 を履歴でなく構造で延伸する。
- **なぜ効くか**: 方角 (3) の直球。decisive negative が出れば A0 はこの語での結論
  (語の交換・fake 路線への転進)へ進める — 「賭けの空振りを待つ」が消える。
- **費用と最初の 1 実験**: 残差 w のダンプ(probe 走行が既に計算しているはず)+
  キー深さ関数 1 本 + frontier 親の深さ分布。1 便。
- **既試行との差分**: 現行の負区間は「rank 1,316 まで無かった」という走行履歴。
  これは今後の全行を縛る不変量。
- **破綻しそうな点**: translation が深さを下げ得る(filtration を保たない)なら障壁が漏れる。
  その場合も「どの translation が深さを下げるか」の分類が札 5 の優先度に転用できる。
- **Sol に確認する 1 問**: 子行生成は親の台の深さを下げ得るか
  (translation は augmentation filtration を保つか)。

## 札 4: 商の階段 — 小商で完走し、negative は本体へ持ち上げ、positive なら hit-rank 写像で発火時期を予測

- **種**: 構成+装置提案。規模: 現在線級。出所: 商での membership 障害の関手性(標準)。

  (小さいので必ず閉じる)。(i) π_k(target) ∉ π_k(V) ⟹ target ∉ V —
  **negative certificate が完走つきで出る**(片側論法・これだけが証明書)。

  発火時期と r を外挿(こちらは統計・札 2 と同格の扱い)。

  負区間 1,316 の延伸を「商の完走」という有限作業で買える。
- **費用と最初の 1 実験**: owner に商パラメタがあるか Sol に確認(なければ blob 切断

- **既試行との差分**: 直接商 v12 系は「一つの商で本番を走る」。これは「商の**列**で

## 札 5: 残差逆引きの優先度つき親開き — closure を A* 化して probe 命中を早める

- **種**: 構成。規模: 現在線級。出所: 標的探索(A*)の翻訳 + v4 dual-guided の教訓。
- **機構の芯**: 親を開く順を「target 残差の台に当たる子行を生む親」優先に変える。
  逆引き: 残差キー k と seed 台キー h から必要 translation t = k·h⁻¹ を group 除算で列挙
  (v4 の q.mul(g, q.inverse(h)) が既にある)し、その t を生む親を優先キューの先頭へ。
  ヒューリスティック h(親) = その親の子が消せる残差 nnz の見積り。残差は増分更新にして
  「probe を打つ」という別作業自体を消す(残差が常時最新 = probe 常時実行と同値)。
- **なぜ効くか**: 方角 (2) の直球。現況⑤の probe は「今の rank 面で見えるか」の賭け —
  盲目順で hit するまでの rank を「残差へ向かう最短系譜の長さ」へ縮める。
  frontier 1,132 が増え続けても、開く順が良ければ hit が先に来る。
- **費用と最初の 1 実験**: 逆引き 1 関数 + 優先キュー化。縮約済み 44-seed の小商版
  フィクスチャで「生成順 vs 優先度順」の hit-rank 比較。1 便。
- **既試行との差分**: 現行の親処理順は不明(生成順と仮定)。v4 の dual-guided は
  「湧いた候補を dual で濾す」供給側フィルタで、ambient 未縮約のまま沈んだ。
  これは「残差から必要行を逆算する」需要側生成 — 縮約後の 1,655 面でこそ効く。
- **破綻しそうな点**: 残差の台が多段 translation の合成でしか届かないと一段逆引きでは
  親が見つからない(二段先読みはコスト増)。greedy が nnz の下がらない高原に嵌まる
  可能性 — ただし高原の検出自体が札 3 の材料になる。
- **Sol に確認する 1 問**: 現行の親処理順は何か(FIFO/生成順/何らかの重み)。

## 札 6: dual 番人 — 分離汎関数を常駐させ、壊れた瞬間だけ probe を打つ(event-driven probe)

- **種**: 構成(証明書)。規模: 現在線級。出所: Farkas 型双対の離散版。
  v12 の PackedEchelon.dual() が実装済みであり「初」ではない — その certificate 用途への転用。
- **機構の芯**: probe 陰性のたびに分離ベクトル φ(φ(span_R) = 0, φ(target) ≠ 0)を保存。
  以後、親を開いて新行 v が出るたび φ(v) を内積 1 回(O(nnz(v)))で評価。
  φ(v) = 0 の間は span が伸びても target は入らない — **probe 不要が証明つき**。
  φ(v) ≠ 0 が出た時だけ φ を更新し target の reduce を進める。副産物 2 つ:
  (a) 「frontier 全親の全子で φ が生き残る」を orbit 論で言えれば札 3 の恒久 negative に直結。
  (b) φ の破壊頻度は hit 接近のメーター(札 2 の系列に足せる)。
- **なぜ効くか**: 方角 (2)(3) 両掛かり。probe+continuation を GHA で回す賭け(現況⑤)を、
  行あたり内積 1 回の常駐監視に置換。負区間の延伸が「φ 生存 rank」として自動記録される。
- **費用と最初の 1 実験**: dual 保持+内積チェックのパッチ(既存 dual() 流用)。
  小商で「番人あり」動作を確認。1 便。
- **既試行との差分**: 現行 probe は特定 rank 面(1,655)での一発勝負(発火条件は不明)。
  これは全 round 常時・数学的に空振りゼロ。
- **破綻しそうな点**: φ 一本は必要条件の監視にすぎない(φ が壊れても membership とは
  限らない)。残差の台が大きいと φ 更新が頻発しコスト逆転 — その場合 φ を複数本
  (残差の各 pivot 座標に一本)持ち、全滅した時だけ full probe に落とす。
- **Sol に確認する 1 問**: 現行 probe の発火条件(周期・rank 閾値・手動)は何か。

## 札 7(飛び道具): 双方向 closure(meet-in-the-middle)— target 側からも半分だけ張る

- **種**: 構成。規模: 現在線級。出所: 双方向探索の翻訳。
- **機構の芯**: target ∈ V の判定を交差検出に変える: target 側の小さい cyclic module
  B = span{t·target}(target の orbit)を張り、B の各元を seed 側 closure A_R で reduce して
  交わりを見る。深さ D の needle に両側から D/2 ずつで会うのが古典的利得(生成が指数分岐
  なら指数的短縮)。mod 3 なので「交わった元が target の ±1 倍か」の最終確認は自明に済む。
  会合点の両側系譜を繋げば exact continuation(現況⑤)の証明書も同時に出る。
- **なぜ効くか**: 方角 (2)。hit までの closure 深度を半減させる。frontier 増加中でも
  会合が先に来る可能性。
- **費用と最初の 1 実験**: まず target の orbit サイズを計算(札 1 と同じ装置)—
  小さければ GO。小商で「片側 vs 双方向」の hit 深度比較。1 便。
- **既試行との差分**: 3 系統も新路線も片側(seed → target)。target 側を張った系譜は
  search/ の名前からは見当たらない(断言はしない・Sol 確認)。
- **破綻しそうな点**: target の orbit が巨大なら B 側も溺れる(札 1 の orbit 番付が前提)。
  交差検出だけでは target 自身の membership に足りない点は上記最終確認で閉じる。
- **Sol に確認する 1 問**: target 側への translation 作用は現行の座標系で
